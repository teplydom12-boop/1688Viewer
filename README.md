# 1688 Viewer

Первая версия расширения Chrome для сбора товаров из поисковой выдачи **1688** в один JSON. Поиск по тексту или картинке вы выполняете на самом маркетплейсе; расширение собирает данные уже открытой выдачи.

**Статус: прототип для проверки на вашей выдаче.** Сборщик проверен в Chromium на подготовленных HTML-примерах, включая переходы между страницами, догрузку и виртуализированные карточки. Сохранение и экспорт проверены через тестовую реализацию API Chrome. Доступ к живому 1688 из этой облачной среды закрыт сетевыми правилами, а установка расширений в облачном Chromium запрещена административной политикой. Полноценный тест установленного расширения на актуальном 1688 пока не выполнен.

## Установка в ваш Chrome

API-ключ ChatGPT, сервер и платные сервисы не нужны.

1. Скачайте `1688-viewer-0.1.0.zip` и распакуйте его. Получится папка `1688-viewer` с `manifest.json`.
2. Откройте `chrome://extensions` в обычном Chrome на компьютере.
3. Включите **Режим разработчика**.
4. Нажмите **Загрузить распакованное расширение** и выберите папку `1688-viewer`.
5. Закрепите расширение через значок пазла на панели Chrome.
6. Если 1688 уже был открыт, обновите вкладку.

Для установки из исходников выбирайте папку `extension`, а не корень репозитория. Если ваш Chrome управляется организацией и запрещает установку расширений, понадобится разрешение её администратора.

Если скачиваете проект с GitHub: нажмите **Code → Download ZIP**, распакуйте архив и при загрузке расширения выберите папку `extension` внутри распакованного проекта. Готовый установочный архив также доступен в сообщении этого чата.

## Первый сбор

1. Откройте 1688, войдите при необходимости и выполните поиск по тексту или изображению.
2. Дождитесь появления карточек и откройте расширение на этой вкладке.
3. Для первого запуска оставьте **1 страницу**. Название поиска необязательно: текстовый запрос берётся из адреса или поисковой строки. Для фотографии можно задать метку, например «Термос — фото 1».
4. Нажмите **Собрать выдачу**. С включённой догрузкой страница прокручивается, и найденные товары накапливаются даже при исчезновении старых карточек из DOM.
5. Проверьте несколько товаров в списке и нажмите **Скачать JSON**.
6. Для следующего запуска можно указать от 1 до 20 страниц. Расширение нажимает доступную кнопку следующей страницы и сохраняет данные после каждой страницы.

Можно закрыть окно расширения: сбор продолжится в целевой вкладке. Сама вкладка должна оставаться открытой; не меняйте поиск во время сбора. При капче, форме входа, ошибке загрузки или повторяющейся выдаче сбор приостанавливается. Пройдите проверку вручную и снова нажмите **Собрать выдачу** — предыдущие результаты сохранятся.

Если кнопку следующей страницы найти не удалось, перейдите вручную и соберите следующую страницу. Когда достигнут предел прокрутки, расширение показывает предупреждение о возможной неполноте. Для продолжения отключите догрузку, прокрутите выдачу дальше вручную и соберите загруженные карточки.

Результаты разных запусков и поисков накапливаются в локальном хранилище расширения, пока вы не нажмёте **Очистить** или не удалите расширение. Повторные товары объединяются по идентификатору предложения; разные товары одного магазина остаются отдельными записями. Перед очисткой скачайте файл.

## Что сохраняется

| Поле | Содержание |
| --- | --- |
| `source` | `1688` |
| `product_id` | Идентификатор предложения, строка |
| `title` | Название товара |
| `product_url` | Ссылка на карточку без параметров отслеживания |
| `shop_name` | Название магазина, если есть в карточке выдачи |
| `supplier_url` | Ссылка на магазин поставщика, если есть в выдаче |
| `price` | Цена или диапазон как отображены на странице |
| `minimum_order` | Минимальный заказ как отображён на странице |
| `image_url` | Ссылка на изображение, без скачивания самого файла |
| `query` | Запрос или ваша метка поиска |
| `search_type` | `text`, `image` или `unknown` |
| `collected_at` | Дата первого сбора товара, ISO 8601 UTC |
| `last_seen_at` | Дата последнего сбора товара |
| `source_page_url` | Адрес выдачи при последнем обнаружении |
| `sightings` | Список поисков и страниц, где встретился товар |

Недоступные значения сохраняются как `null`. Например, отсутствие минимального заказа в выдаче не означает, что заказа нет. Цена и минимальный заказ остаются строками: расширение не угадывает валюту, единицы и условия скидок. При повторном обнаружении пустые поля не затирают уже найденные значения.

В корне файла находятся `schema_version`, `source`, `exported_at`, `total_products`, `pages` и `products`. Список `pages` содержит сведения о собранных страницах и предупреждения о возможной неполноте. Изображения, HTML страниц, cookies и данные входа в файл не включаются. Расширение не отправляет результаты на внешний сервер; прокрутка и переходы используют обычную работу сайта 1688.

Пример одного товара:

```json
{
  "source": "1688",
  "product_id": "1001",
  "title": "透明水杯 500ml",
  "product_url": "https://detail.1688.com/offer/1001.html",
  "shop_name": "浙江水杯工厂",
  "supplier_url": "https://cupfactory.1688.com/",
  "price": "¥12.50",
  "minimum_order": "2件起批",
  "image_url": "https://cbu01.alicdn.com/img/ibank/cup.jpg",
  "query": "水杯",
  "search_type": "text",
  "collected_at": "2026-10-14T00:00:00.000Z",
  "last_seen_at": "2026-10-14T00:00:00.000Z",
  "source_page_url": "https://s.1688.com/selloffer/offer_search.htm?keywords=%E6%B0%B4%E6%9D%AF",
  "sightings": []
}
```

Это вымышленные данные для иллюстрации формата.

## Ограничения первой версии

- Поддерживается 1688. Alibaba и Made-in-China пока не подключены.
- Собираются доступные данные из выдачи. Переход в каждую карточку, группировка по компаниям и мониторинг будут отдельными этапами.
- Разметка 1688 меняется и может отличаться для обычной выдачи, поиска по фото, рекламы и разных аккаунтов. Используются DOM-правила, а не недокументированные API. На вашей выдаче могут потребоваться дополнительные правила.
- Капчи и вход выполняются вручную. Полнота всей выдачи и охват всех поставщиков не гарантируются.
- Если вы видите товары, а расширение сообщает «Товары не найдены», нужны примеры разметки карточек. Для диагностики можно передать сохранённый HTML отдельной карточки без данных входа и личной информации.

## Разработка и проверки

Приложение в браузере не требует установки npm-зависимостей или отдельного сервера. Зависимости нужны только для проверок разработчика.

Требуются Node.js 22+, Python 3 для архива и Chromium для браузерных тестов. По умолчанию используется `/usr/bin/chromium`; другой путь можно задать через `CHROMIUM_PATH`.

```bash
cd /workspace/1688Viewer
npm ci --cache /tmp/1688viewer-npm-cache --ignore-scripts --no-audit --no-fund
npm run check
npm test
npm run package
```

В `dist/1688-viewer-0.1.0.zip` попадут только расширение и инструкция. `node_modules`, тесты, данные сборов и облачные настройки в архив не включаются.

`npm test` проверяет реальные DOM-страницы в Chromium и фоновые операции с тестовой реализацией Chrome API. Установка расширения, браузерные разрешения и нативное скачивание проверяются отдельной командой:

```bash
npm run test:extension
```

Для неё нужен Chromium с поддержкой CDP `Extensions.loadUnpacked` и без административного запрета на установку расширений. **В текущей облачной среде этот тест блокируется политикой `ExtensionInstallBlocklist: ["*"]`; это не пройденная проверка.** При запрете не меняйте системные политики — выполните проверку в разрешённой среде. Все браузерные тесты используют искусственные страницы и не подтверждают работу на живом 1688.

Файлы:

- `extension/content.js` — извлечение полей, прокрутка, обнаружение следующей страницы.
- `extension/background.js` — накопление, остановка и возобновление заданий, экспорт.
- `extension/shared.js` — нормализация ссылок и объединение товаров.
- `extension/popup.*` — интерфейс на русском языке.
- `tests/` — примеры разметки и проверки.
