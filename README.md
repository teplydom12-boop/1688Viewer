# Supplier Viewer 0.16

[Скачать готовое расширение 0.16.0 (.zip)](https://github.com/teplydom12-boop/1688Viewer/raw/refs/heads/main/releases/supplier-viewer-0.16.0.zip)

Расширение Chrome для сбора товаров и поиска поставщиков на **1688, Alibaba, Made-in-China и других сайтах с карточками товаров**. Вы выполняете поиск по тексту или фото средствами сайта. Расширение собирает выдачу, продолжает её через страницы или догрузку, сохраняет задания в общей памяти и показывает **таблицу поставщиков с деревом найденных товаров**.

## Полнота выдачи и отдельный список исключённых поставщиков — версия 0.16

Лимит страниц — верхняя граница задания. Если на сайте две страницы, а задано десять, сбор завершается успешно после второй, с фактическим количеством страниц и сохранением всех результатов. Конец выдачи подтверждается отключённым переходом, в том числе отдельной кнопкой Load more, явными данными сайта или полной последовательностью номеров в пагинации, где текущая страница последняя и нет продолжения либо многоточия. Одна страница с явным общим числом страниц 1 также завершается нормально. Простое отсутствие распознанной кнопки не доказывает конец: неоднозначная навигация и капча по-прежнему ставят работу на паузу.

Исправлен завышенный ориентир полноты после страниц с большим числом повторных строк. Историческое сравнение теперь использует **уникальные предложения на обеих страницах**, а не общее число сохранённых появлений: например, 251 строка с 60 уникальными товарами больше не требует 251 строку на следующей странице. Если сайт явно сообщает размер страницы, он по-прежнему сопоставляется с количеством карточек. Все повторные появления сохраняются. Настоящая недогрузка, старая выдача после перехода и несовпадение номеров страниц продолжают обнаруживаться. В сообщении об ошибке отдельно указаны строки, уникальные товары и единица ориентира. Уже приостановленное задание можно продолжить после обновления; его прежний отпечаток используется для исправленного ориентира.

После отбора Claude основной список содержит поставщиков с хотя бы одной включённой карточкой. **Поставщики только с категорией «Не подходит» сохранены отдельно** в раскрываемой категории «Не подходят — проверка пропущена»: у каждого показаны магазин и его найденные карточки. Они не увеличивают основной счётчик поставщиков. У продавца с разными категориями включённые товары остаются в основном дереве, а неподходящие сохранены рядом со сведениями об этом же продавце в отдельной категории. Сомнительные и неоценённые карточки остаются включёнными. Неизвестные продавцы исключённых карточек — отдельная группа, не одна подтверждённая компания. Цены и условия не используются для отбора.

JSON этапа 2 добавляет `excluded_suppliers`, `total_excluded_suppliers` и `excluded_unknown_cards`. У поставщиков основного списка `excluded_products` сохраняет их собственные исключённые карточки; общий `products` содержит все строки. Совпадение компании определяется по ID или адресу магазина внутри площадки. Excel с отбором содержит отдельные листы **Поставщики**, **Исключённые карточки** и **Исключённые поставщики**; на последнем только продавцы без включённых товаров и отдельная строка неизвестных продавцов. CSV сохраняет все строки и добавляет колонку **Раздел поставщиков**. Ручное возвращение карточки или сброс отбора сразу пересчитывают группы, не переписывая этап 1 и не открывая исключённые карточки.

## Ручной отбор через Claude без API — версия 0.15

На этапе 2 появился необязательный раздел **Отбор карточек через Claude**. Расширение формирует файлы, вы вручную передаёте их в Claude и загружаете файл с решениями обратно. API-ключ, связующий сервер, плагин Claude и автоматические обращения к AI-сервисам не требуются. Подойдёт и другой помощник, который соблюдает формат ответа.

1. Выберите задания и нажмите **Обработать выбранные задания**.
2. В поле **Какой товар ищем** укажите товар и существенные требования: например, «Самостоятельный сетевой дровокол 220 В, не аккумуляторный, не запчасти и не насадка для экскаватора».
3. Нажмите **Скачать инструкцию** и **Скачать JSON для Claude**. Прикрепите оба файла в диалог Claude и попросите выполнить инструкцию, сохранив результат отдельным JSON-файлом. Инструкция также включена в сам JSON.
4. Нажмите **Загрузить решения Claude** и выберите полученный файл. Можно выбрать несколько ответов разных частей сразу.
5. Просмотрите категории и причины. Нажмите **Проверить поставщиков**. После завершения скачайте JSON или Excel итогового результата.

По умолчанию выгружаются **все уникальные названия одним JSON-файлом**. В поле **Объём файла для Claude** можно выбрать порции по **100 / 200 / 500 названий**. Ограничение в 200 в версии 0.14 было выбранным размером порции, чтобы снизить риск обрезания ответа, а не лимитом сайта или расширения. Большой файл допустим, но контекст диалога и длина ответа Claude ограничены и зависят от модели и режима. Если ответ не помещается, выберите порции или попросите корректный частичный JSON; отсутствующие решения остаются неоценёнными.

**Анализ только по названию.** Для каждой записи передаются только `id` и `title`; отдельно — описание искомого товара и инструкция. Изображения, ссылки, магазин, площадка, число повторов, цена, условия, исходная разметка и приватные поля в задание не включаются. Инструкция запрещает искать и использовать изображения. Расширение не управляет поведением внешнего помощника, поэтому передавайте ему только подготовленные файлы.

Полностью совпадающее сохранённое название отправляется **один раз**, включая совпадения у разных предложений и на разных сайтах. Результат применяется ко всем строкам с этим названием; сами строки, ID предложений и поставщики не объединяются. Разный регистр, пробелы, знаки и переводы не считаются совпадением. Разные названия одного предложения оцениваются отдельно: если хотя бы одно его появление остаётся включённым, предложение может участвовать в проверке поставщика. Счётчик отбора показывает **названия**, а итоговые счётчики уникальных карточек по-прежнему используют площадку и ID/ссылку.

Выбор **Часть 1 / 2 / …** показывает, сколько названий части уже оценено. Порции используют общее задание; импорт следующих частей дополняет предыдущие решения. Смена размера порций сохраняет принятые категории, но создаёт новый ID задания — скачайте новые файлы, старые ответы больше не подойдут. Сохранённые задания версии 0.14 и их ответы доступны для импорта до создания нового задания через скачивание инструкции или JSON; новый экспорт переводит их на отбор по названиям и сбрасывает прежние категории.

Категории: **Подходит**, **Нужно уточнить**, **Не подходит**, **Не оценивалась**. По умолчанию в проверку поставщиков включены все, кроме **Не подходит**. Если не экспортировать задание либо не загрузить решений, проверяются все карточки. Частичный ответ оставляет пропущенные карточки неоценёнными; они тоже проверяются. Для исключения ответ должен содержать причину и подтверждающую цитату из названия. Неподтверждённое исключение переводится в **Нужно уточнить**. Эта проверка не доказывает правильность смыслового решения модели: просматривайте объяснения и при необходимости меняйте категорию вручную.

В таблице есть фильтр категорий и отдельная группа **Не подходят — проверка пропущена**. Раскройте дерево, чтобы увидеть причину и цитату; выпадающий список позволяет исправить решение для всех карточек с таким же точным названием. Повторный импорт не отменяет ручные решения. Кнопка **Сбросить отбор: проверять все** возвращает все карточки в неоценённые, сохраняя их и возможность снова загрузить ответы того же задания. Для полной повторной проверки уже открытых карточек подготовьте этап 2 заново.

Изменения отбора доступны после остановки проверки. Возобновление учитывает ранее завершённые проверки и не открывает их повторно; добавленные обратно карточки попадают в оставшуюся очередь. Счётчики открытий относятся ко всему заданию, включая переходы до изменения категорий. Капча по-прежнему требует ручной проверки; изменение категории не обходит её. Исходные снимки этапа 1 не переписываются.

При изменении описания скачайте новый JSON: это создаёт новое задание для Claude и сбрасывает прежние категории, сохраняя все карточки и уже полученные сведения о продавцах. Старые ответы после этого отклоняются. Проверяются ID задания, часть, принадлежность ID карточек, категории и типы полей. Некорректный или противоречивый набор файлов отклоняется целиком, без частичного изменения памяти. Нельзя подменить ссылки, названия или поставщиков через файл решений. Допускаются JSON и цельный ответ в блоке JSON; произвольный текст вокруг ответа и обрезанный JSON нужно исправить в Claude. До 100 файлов за импорт, каждый до 16 МиБ, вместе до 32 МиБ.

Формат ответа — копия `response_template` из скачанного файла с заполненным `decisions`:

```json
{
  "schema_version": 1,
  "report_type": "relevance_decisions",
  "request_id": "скопировать из входного файла",
  "batch_id": "скопировать из входного файла",
  "decisions": [
    {"id": "card_000001", "status": "uncertain", "reason": "Тип питания не указан", "evidence": ""}
  ]
}
```

Значения `status`: `relevant`, `uncertain`, `excluded`. Для `excluded` обязательны объяснение и цитата `evidence` из одного исходного названия. ID копируются без изменений. Для следующей части используйте её собственный шаблон ответа; у неё другой `batch_id`.

**Все исходные появления остаются в выгрузке.** JSON этапа 2 содержит полный массив `products`, отдельный `excluded_products`, категории и причины в `products[].relevance` и сводку `relevance`. Деревья `suppliers` содержат только включённые карточки; исключённые не создают компании в итоговом списке. CSV также содержит все строки с категориями и причинами. Excel сохраняет все строки на листах **Товары** и **Товары заданий**, добавляет колонки категории, причины и цитаты. Если создано задание для Claude, появляется лист **Исключённые карточки**; лист **Сводка этапа 2** показывает категории и их количество. Картинки и управление их качеством сохранены. Формат Excel этапа 1 остаётся прежним.

**У каждого повторного появления своё превью**, если изображение доступно и показ картинок включён. Это относится к истории, деревьям этапа 2 и каждой строке Excel, включая исключённые карточки. Общий файл фотографии может скачиваться и храниться один раз, но его отображение повторяется в каждой строке. Исправлена коллизия превью в истории при одинаковых или отсутствующих идентификаторах наблюдения старых карточек.

## Уникальные карточки, уведомления и Excel этапа 2 — версия 0.13

На этапе 2 отдельно показаны **все карточки**, **уникальные карточки** и **повторные появления**. В строке каждого поставщика есть общее и уникальное количество; для неизвестных продавцов тоже приводится число уникальных карточек. На маркетплейсах ключом служит площадка + ID предложения, при отсутствии ID — ссылка. Для обычных сайтов используется полная нормализованная ссылка, включая вариант товара; служебные метки отслеживания удаляются. Без ID и ссылки строки считаются отдельными, так как подтвердить их совпадение нельзя. Например, три появления одного предложения в двух заданиях — три строки и одна уникальная карточка. Все появления остаются в памяти, дереве и экспорте; совпадение названий или картинок их не объединяет.

JSON этапа 2 сохраняет `schema_version: 1` и прежние поля; добавлены `duplicate_cards`, `unknown_unique_offers` и счётчики `unique_offers` / `duplicate_cards` у каждой группы поставщика. Общее число уникальных предложений не равно числу необходимых открытий: известные магазины и положительный кэш позволяют обойтись без части переходов.

**При капче или запросе входа во время проверки карточек** работа ставится на паузу с сохранённой очередью. Расширение отправляет системное уведомление Chrome и показывает красный **!** на значке. Нажатие на уведомление или его кнопку открывает рабочую вкладку. В интерфейсе этапа 2 и popup есть заметное предупреждение со ссылкой на эту вкладку. Пройдите проверку вручную, затем нажмите **Продолжить** на этапе 2; пока проверка остаётся на странице, возобновление блокируется.

Для этого добавлено разрешение Chrome `notifications`. Если при обновлении браузер запросит новое разрешение, подтвердите доступ к уведомлениям. Их отображение зависит от настроек Chrome и операционной системы; при недоступности API остаются значок и предупреждения в интерфейсе. Одна остановка не вызывает повторных уведомлений при обновлении вкладки или перезапуске фонового процесса. Новая капча после продолжения создаёт новое уведомление. Продолжение, пропуск, подготовка другого задания, удаление связанной проверки и очистка памяти убирают прежний сигнал. Уведомления не отправляются во внешние сервисы.

Кнопка **Скачать таблицу Excel (.xlsx)** теперь есть непосредственно у раздела **Таблица поставщиков**, помимо кнопки в шапке. Она открывает подготовку Excel для текущего результата этапа 2: выберите качество картинок или сохранение без них и нажмите **Сохранить Excel**. Доступны и окончательный, и предварительный результаты, с соответствующей пометкой. Файл включает только выбранные задания и все их найденные карточки с повторами.

На листе **Поставщики** — ссылки на магазины, общее и уникальное количество карточек, число повторов и статус. Группа **Поставщик неизвестен** включена отдельной строкой и не увеличивает число определённых компаний. На листе **Товары** и **Товары заданий** указаны продавцы, ссылки на карточки, ключ уникального предложения и число его появлений во всех выбранных заданиях. Лист **Сводка этапа 2** содержит общие счётчики, состояние результата и ход проверки карточек. Прежние изображения, качество и сворачивание столбца фото в Excel 2016/2019/2021 сохранены; экспорт этапа 1 сохраняет прежние четыре листа.

Исправлено распознавание магазинов Alibaba на доменах **`*.trustpass.alibaba.com`**: ссылка на профиль компании теперь определяется так же, как `*.en.alibaba.com`, и нормализуется до адреса магазина. Исправление применяется при новом сборе и чтении карточек на этапе 2. Уже сохранённые снимки этапа 1 автоматически не переписываются. Для повторной проверки старого результата заново подготовьте этап 2 на тех же заданиях; подтверждённые записи кэша по-прежнему помогают сократить очередь.

## История, цены и обработка больших страниц — версия 0.12

**История проверок** выделена в навигации, в popup и отдельной заметной ссылкой на основном экране. В таблице заданий можно сразу открыть память нужной проверки. Прежний выпадающий список **Показать результаты** перенесён в закрытый по умолчанию блок **Дополнительный просмотр общей памяти**. Основной способ работы с отдельными выгрузками — история.

Внутри проверки доступны два вида: **Карточки** и **Поставщики и дерево карточек**. Выберите **Порядок по цене → По возрастанию / По убыванию**. Поставщики сортируются по минимальной цене среди своих найденных карточек, а карточки — по собственной цене. Диапазон используется по нижней границе. Внутри раскрытого поставщика карточки тоже сортируются. Нечитаемые и отсутствующие цены остаются в конце, группа неизвестных продавцов — после установленных поставщиков.

Разные валюты образуют отдельные группы и не пересчитываются. Фильтр **Валюта** позволяет рассмотреть одну валюту. Если у поставщика есть цены в разных валютах, общая минимальная цена не выдумывается: выберите валюту. Обозначение ¥ без кода на трёх китайских площадках трактуется как CNY; на произвольном сайте остаётся отдельным обозначением. Неуказанная валюта тоже отделена. Порядок и вид сохраняются между вкладками и перезапусками. Сортировка и фильтр служат для просмотра: память, повторы, исходный порядок выгрузки и состав заданий этапа 2 остаются прежними. Эти цены не определяют условия закупки и не используются для отбора поставщиков.

Исправлены проблемы из присланных снимков: название магазина извлекается из ссылки компании, а не из контейнера со всплывающей информацией, значками и статистикой; сертификаты CE, значки проверки, стрелки и флаги не выбираются вместо фото товара. Контекст известной карточки учитывается перед общими структурными эвристиками. Отдельные появления одного предложения в разных карточках по-прежнему сохраняются.

Повторный разбор ускорен за счёт кэша областей DOM, текста, ссылок и изображений **только внутри одного синхронного чтения**. Между чтениями кэш сбрасывается, поэтому изменения цены, названия, ссылки и картинки не становятся устаревшими. Во время прокрутки неизменные карточки повторно не разбираются целиком на каждом шаге; загрузка байтов изображений и изменения только `img.src` не задерживают ожидание тишины DOM. Перед завершением есть обязательное свежее чтение для обновления картинок. Изменения структуры, текста, ссылок и цен по-прежнему отслеживаются, включая кратковременные и виртуализированные карточки.

Устранено молчаливое обрезание массивов после 300 элементов; чтение данных страницы и наблюдаемых ответов допускает до 2000 записей. Приоритет отдан спискам товаров, пагинации и бизнес-данным, служебные ссылки React `_owner` и приватные поля пропускаются. Сохраняются ограничения времени (150 мс для одного MAIN-чтения), объёма структуры и очереди (20 000), дочерних элементов (5000 в массиве, 1000 в объекте) и размера наблюдаемого JSON-ответа (2 МиБ). Геттеры не вызываются.

Диагностика различает **недочитанные известные данные** (`data_truncated`, `data_truncation_reasons`) и ограничение дополнительного поиска компонентов (`component_discovery_limited`). В первом случае предупреждение сохраняется и называет причину, когда она известна: время, число записей, размер списка, структура или очередь. Найденные DOM-карточки сохраняются; проверка полноты страницы выполняется отдельно. Ограничение поискового обхода компонентов само по себе не означает, что известный список товаров обрезан. Полная доступность любых данных сайта не гарантируется.

Изменения извлечения названий и изображений применяются при новом сборе или переразборе доступной исходной разметки. Уже сохранённые результаты автоматически не переписываются. Внешние AI-модели и фильтрация релевантности в этой версии не подключаются; сбор сохраняет все найденные карточки.

## Этап 2, поиск поставщиков — версия 0.11

Откройте **Этап 2, поиск поставщиков** из popup, основной таблицы или истории. Выберите несколько сохранённых заданий этапа 1 — с одной площадки или с разных сайтов. Доступны завершённые, остановленные и приостановленные задания с сохранёнными карточками; выполняемое задание сначала нужно поставить на паузу. Отдельные старые задания обогащения не включаются в выбор.

1. Нажмите **Обработать выбранные задания**. Программа создаёт отдельный снимок выбранных карточек, использует сохранённые сведения о магазине и ранее проверенные связи «предложение → продавец». Сетевых переходов на этом шаге нет. Цена и минимальный заказ не влияют на включение в результат. Все появления карточек, в том числе повторы внутри задания и между заданиями, остаются в таблице и JSON; исходная память этапа 1 не изменяется.
2. Если ссылка на магазин уже известна, карточку открывать не нужно даже при отсутствии названия компании: вместо него отображается адрес магазина. Надёжный идентификатор поставщика позволяет дополнить остальные его найденные карточки сведениями о том же магазине. При отсутствии ссылки нужна одна показательная карточка на известный ID поставщика; при отсутствии личности продавца — одна проверка каждого уникального предложения. Совпадение названий или фотографий не объединяет продавцов. Идентификаторы разных площадок не объединяются между собой. Противоречивые сведения требуют проверки.
3. Укажите **Интервал после проверки** от **1 до 300 секунд** (по умолчанию 5) и нажмите **Открыть карточки**. Для сторонних сайтов Chrome запросит доступ только к нужным доменам. Программа последовательно использует одну отдельную рабочую вкладку и открывает только товары из выбранных заданий. Поиск полного ассортимента магазина не выполняется. Интервал можно изменить кнопкой **Применить интервал** во время работы; он выдерживается после завершения предыдущей проверки.
4. Прогресс показывает текущую операцию и карточку, число запланированных, открытых, проверенных и оставшихся карточек. Повторное чтение той же карточки после капчи не увеличивает число разных открытых карточек очереди. Примерное время учитывает интервал и среднюю длительность выполненных проверок; до первой проверки это ориентир. Состояние, очередь и время следующего перехода сохраняются между закрытиями интерфейса и перезапусками фона. При закрытии рабочей вкладки программа ставится на паузу; продолжение создаст новую рабочую вкладку.
5. При капче, входе, ограничении частоты или ошибке работа останавливается. Нажмите **Рабочая вкладка / капча**, вручную завершите проверку и нажмите **Продолжить**. Нерешённая видимая капча блокирует продолжение и не вызывает новый переход. Интервал уменьшает частоту обращений, но не гарантирует отсутствие ограничений. Этапы 1 и 2 не выполняются одновременно.
6. **Пропустить проверку карточек и получить итог** завершает задание сразу с уже полученными сведениями, в том числе во время паузы или чтения текущей карточки. Поздний результат прерванной проверки не меняет итог, следующая карточка не открывается. Неустановленные продавцы попадают в группу **Поставщик неизвестен**; это группа карточек, а не одна вымышленная компания. Известный ID при недоступной ссылке сохраняется; имя и адрес не выдумываются.

В таблице нажмите на поставщика, чтобы раскрыть дерево **только его найденных карточек**. Каждая строка содержит ссылку на товар, площадку, исходное задание, изображение и сведения о проверке. Доступны поиск, раскрытие/сворачивание всего дерева и прежние настройки показа/размера картинок. Отображаются все сохранённые появления, цены не используются для отбора.

**JSON** этапа 2 имеет `report_type: "supplier_search"`, `schema_version: 1`, `scope: "only_cards_from_selected_tasks"`, список `source_tasks`, счётчики `card_checks`, массив `suppliers` с вложенными `products` и полный плоский массив `products`. У каждой карточки есть `source_task_id`, `source_task_name`, `stage2_row_id` и отдельный объект `supplier` с полями `source`, `supplier_id`, `shop_name`, `supplier_url`, `method`, `checked_at`. Первоначальные поля карточки сохранены для проверки происхождения. Идентификатор и URL имеют приоритет над названием при определении продавца. Для неопределённых карточек в дереве используется буквальная метка «Поставщик неизвестен».

Кнопка **Excel** открывает обычный экран экспорта с качественными встроенными картинками и выгружает только выбранный результат этапа 2. В листах товаров используются уточнённые продавцы; неустановленные отмечены как «Поставщик неизвестен». CSV содержит поставщика, магазин, площадку, статус, товар, ссылку, задание и ID наблюдения. Предварительную таблицу тоже можно экспортировать: JSON отражает её текущий статус. Для окончательного результата закончите очередь либо пропустите её.

Текущая таблица этапа 2 сохраняется локально. Подготовка другого набора заданий заменяет эту таблицу; для отдельного архива сохраните JSON или Excel. Успешные проверки продавца сохраняются в техническом кэше и используются в следующих запусках, не добавляя в результат товары из невыбранных заданий. Удаление исходного задания удаляет зависящий от него текущий результат этапа 2 и сбрасывает кэш проверок; очистка всей памяти удаляет этап 2 и кэш полностью. Цены, карточки и снимки этапа 1 не перезаписываются обогащением этапа 2.

Проверка карточки использует имеющийся движок DOM, структурированных данных и состояния страницы в обычном браузере. Продавец из рекомендации другого товара не переносится на проверяемое предложение; неоднозначные ссылки оставляются неподтверждёнными. Поля, которые сайт не отдал или которые движок не смог связать с товаром, остаются неизвестными. Программа не может гарантировать извлечение продавца при любой разметке. Обработка полностью локальная, внешних AI-сервисов нет.

## Размер картинок и качество Excel — версия 0.10

В истории откройте память проверки и нажмите **Показать картинки**. Ползунок **Размер картинок** меняет сторону превью от **32 до 192 px** с шагом 16, по умолчанию 48 px. Размер меняется сразу во время перетаскивания, без перезагрузки изображений; текст и ссылки остаются обычного размера. Кнопка **Скрыть картинки** возвращает компактные ссылки. Настройки размера и показа сохраняются между вкладками и перезапусками браузера. Можно выбрать размер до включения картинок — в скрытом режиме они не загружаются. Недоступное изображение оставляет ссылку с пометкой. Удаление одной проверки сохраняет настройки, очистка всей памяти сбрасывает их.

Кнопка **Excel** в popup, основной таблице или истории открывает экран экспорта. Галочка **Включить компактные картинки в файл** включена по умолчанию. Выберите **Качество картинок**: стандартное — до **384 × 384**, высокое — до **768 × 768** (по умолчанию), максимальное — до **1280 × 1280**. Выбор сохраняется. Нажмите **Сохранить Excel**: Chrome при необходимости запросит доступ только к серверам изображений из выбранной выгрузки. Прогресс показывает успешные и недоступные изображения; подготовку можно отменить. Без галочки файл сохраняется со ссылками и не запрашивает доступ к серверам картинок.

Ранее изображения принудительно уменьшались до 96 × 96 с качеством JPEG 0.82. Теперь используются JPEG 0.90 / 0.94 / 0.96 в зависимости от режима. Изображение вписывается в квадрат без изменения пропорций; небольшие исходники не увеличиваются искусственно. Чёткость ограничена реальными деталями исходного файла. После экспорта отображается количество исходников меньше 256 px. Выше качество — больше размер файла. Чтобы улучшить картинки в ранее выгруженной таблице, создайте Excel заново из сохранённой памяти.

Новый сбор предпочитает явный `data-original` и наиболее крупный `srcset` перед маленькой загруженной картинкой. В истории и экспорте для известных суффиксов миниатюр `alicdn.com` выполняется попытка загрузить оригинал на том же сервере. Если он недоступен, используется сохранённая ссылка на миниатюру. Подписанные URL с распознанными параметрами подписи, неизвестные домены, имена файлов и преобразования в query не переписываются. Исходная ссылка в старой памяти и выгрузке сохраняется.

В Excel 2016 / 2019 / 2021 на листах **Товары** и **Товары заданий** картинки по-прежнему располагаются в границах компактных ячеек. Нажмите стандартный **− над столбцом фото**, чтобы скрыть его вместе с изображениями, или **+**, чтобы вернуть. На каждом листе свой переключатель. Если символы структуры отключены в Excel, включите «Показывать символы структуры, если структура применена» в параметрах отображения листа. Строки имеют высоту 36 пунктов; скрытие столбца не меняет высоту строк. Разрешение сохранённой картинки больше её размера на листе, поэтому при увеличении доступно больше деталей.

Используются встроенные рисунки с привязкой «перемещать и изменять размер вместе с ячейками», совместимые со старыми версиями Excel. Макросы, `IMAGE()` и внешние связи не нужны. В книге отключено автоматическое сжатие картинок (`autoCompressPictures=0`), чтобы уменьшить повторную потерю качества при сохранении в Excel. Изображения хранятся в `.xlsx` и после экспорта доступны без Интернета; ссылки на оригиналы остаются отдельным текстовым полем.

Обработка локальная: до четырёх загрузок одновременно, 8 секунд на попытку, максимум 8 МБ и 40 миллионов пикселей на исходник. Повторная попытка по сохранённой ссылке получает отдельный таймер. Общий предел встроенных изображений увеличен до **128 МБ**. Одинаковая ссылка загружается и встраивается один раз, даже если у неё несколько строк наблюдений. Недоступные, перенаправляемые и слишком большие изображения пропускаются с пометкой «Нет миниатюры»; товары и исходные ссылки сохраняются. Данные не отправляются в AI-сервисы. Разрешения на серверы изображений можно отозвать в настройках Chrome.

## Сбор без удаления дублей — версия 0.9

Каждая распознанная карточка сохраняется отдельной строкой, даже если ID товара и ссылка уже встречались на этой странице, на других страницах или в прошлых заданиях. Разные цены, минимальные заказы и прочие показанные поля у повторных карточек не заменяют друг друга. Счётчики, история, таблица поставщиков и JSON / CSV / Excel учитывают все строки. Например, две подтверждённые страницы по 60 карточек дают 120 записей, даже если часть товаров повторяется. Фильтрация и удаление дублей остаются следующим этапом и автоматически не выполняются.

Новые записи содержат **ID записи** (`observation_id`), **ID задания** (`task_id`), **страницу задания** (`page_index`), **позицию карточки** (`card_index`), адрес выдачи, запрос, дату и **статус записи** (`capture_status`). Статус `confirmed` означает сохранённую страницу, `partial` — незавершённую контрольную точку, `imported` — строку из импортированного файла. Эти поля добавлены в JSON и отдельными колонками в Excel / CSV. `product_id` по-прежнему обозначает предложение и может повторяться; `observation_id` обозначает конкретную сохранённую строку. Позиция соответствует порядку распознавания и может отличаться от визуального порядка при сборе из данных приложения.

Техническое перечитывание той же карточки во время прокрутки, загрузки полей или продолжения после паузы обновляет её строку в текущей контрольной точке. Успешное продолжение заменяет незавершённый снимок страницы и сохраняет ID уже известных позиций. При «Загрузить ещё» сохраняются вновь добавленные позиции, включая карточки с уже известным ID; старые позиции остающегося на экране списка не копируются повторно. Распознавание из DOM, JSON-LD, данных приложения и ответов объединяет представления одной карточки, но сохраняет повторные карточки в списке. Если сайт виртуализирует полностью одинаковые карточки и не даёт ни позиции, ни других отличимых признаков, точно различить их отдельные появления невозможно.

Переход может подтверждаться номером показанной страницы, новым документом по другому адресу или изменившимся содержимым карточек после нажатия. Новый ID товара больше не является обязательным условием: следующая страница может целиком состоять из повторов. При неизменной странице кнопка не нажимается в цикле. Неоднозначность, несовпадение номера страницы и признаки незавершённой загрузки по-прежнему вызывают паузу. Уже увиденные карточки сохраняются как `partial` вместе с диагностикой; неподтверждённая страница не увеличивает прогресс. Капча и продолжение одной кнопкой сохранены.

Импорт сохраняет все строки файла, включая одинаковые строки и повторный импорт того же файла. Каждому импорту назначается свой `import_batch_id`, строкам — новые `observation_id`; исходные ID записи и задания доступны как `imported_observation_id` и `imported_task_id`. История заданий из файла по-прежнему не импортируется. Удаление проверки удаляет только её наблюдения; строки остальных проверок и независимых импортов сохраняются. Переразбор исходников сохраняет повторные записи, а его импорт добавляет новую порцию в память.

Существующая память сохраняется без сброса. Повторы, уже объединённые прежними версиями, автоматически не восстанавливаются: для полного исходного набора нужен новый сбор. Старые строки могут не содержать новых полей происхождения. Схема JSON остаётся **3**, добавлен маркер `collection_mode: "all_cards"`.

## Проверка полноты выдачи в версии 0.7

Сбор дожидается появления новой выдачи, прежде чем включить накопление карточек наблюдателем. После перехода проверяются все ID ранее подтверждённых страниц задания, а не только предыдущая страница. Если есть свежие DOM-карточки, старые записи из состояния приложения без соответствующей DOM-карточки не подмешиваются к новой выдаче.

Перед сохранением проверяются количество найденных, новых и повторных ID. Явный номер страницы в URL сопоставляется с номером загруженных карточек (`page_num` на 1688) или доступным индикатором текущей страницы. Несовпадение либо смешение номеров означает, что переход ещё не подтверждён; URL без явного номера не трактуется как первая страница. Выдача из большого числа старых товаров и одного нового не считается успешной страницей. При включённой прокрутке явный размер страницы сравнивается с количеством карточек, а исторический ориентир — с числом уникальных предложений предыдущей подтверждённой страницы: сильное недозаполнение вызывает ожидание и паузу. Настройка `page_size@60` из карточек 1688 также распознаётся. Маленькая последняя страница с подтверждённым концом пагинации допускается. Явная кнопка «Load more / Загрузить ещё» на том же адресе учитывается как дополнение списка: наличие старых карточек в таком режиме ожидаемо и не вызывает ложную паузу. Это проверка по признакам, а не гарантия фиксированного числа товаров на любом сайте.

При неподтверждённой полноте задание получает состояние **Пауза**, страница не засчитывается, а все увиденные карточки сохраняются отдельными частичными строками. Строки подтверждённых страниц не изменяются. При несовпадении номеров сохраняются частичный снимок и диагностика; такой снимок нельзя считать подтверждённой страницей. Дождитесь загрузки или обновите выдачу на том же адресе, затем нажмите **Продолжить**. Сохранённая часть заменяется полной контрольной точкой, когда сбор подтверждён. Диагностика `collection_quality` содержит ожидаемое и фактическое количество, новые/повторные ID и признак последней страницы. Новые ID здесь считаются относительно уже подтверждённых страниц, без частичного результата текущей страницы.

В popup крупные счётчики и список товаров относятся к текущему заданию и начинают с нуля при новом запуске. Общая память сохраняется; её размер указан отдельно. Кнопки popup **Вся память: JSON / Excel** выгружают все задания, а выбранную проверку можно выгрузить из истории.

На всех листах Excel есть колонка **Сайт-источник**, например `1688.com`, `alibaba.com` или `made-in-china.com`. На листах товаров также есть **Адрес сайта-источника** с фактическим origin выдачи и **Страница выдачи** с её полным адресом. JSON сохраняет прежние коды `source`.

У изображений исключены флаги стран, маленькие служебные иконки и известные заглушки. Ссылки на товар Made-in-China больше не интерпретируются как ссылки на магазин. Границы глубоко вложенной карточки учитывают соседние ID, а скрипты/шаблоны не участвуют в определении текста и размера карточки.

Уникальные товары и число наблюдений на страницах различаются: один товар может повторяться в выдаче. Проверка не обещает 600 уникальных предложений при 10 страницах по 60 карточек. Сохранённый HTML виртуализированной выдачи может содержать только видимую часть, например 15 карточек; отсутствующие карточки из такого снимка восстановить нельзя. Пользовательские отчёты не входят в репозиторий или установочный архив.

## История проверок в версии 0.6

Откройте **История проверок ↗** из popup расширения или шапки основной таблицы. История открывается в отдельной вкладке браузера и показывает все записанные задания: название, дату, площадку, состояние, страницы и количество товаров. Доступен поиск по названию, площадке и состоянию.

- **Открыть память** показывает снимок конкретной проверки: товары, цены, минимальный заказ, магазины, ссылки, изображения, даты, сохранённые страницы и журнал. Фрагмент адреса сохраняет выбранную проверку, поэтому её можно открыть снова после перезагрузки вкладки. Данные выполняемого задания обновляются автоматически.
- **JSON этой проверки**, **Excel этой проверки** и **Исходники этой проверки** выгружают только выбранное задание. Верхние кнопки **Вся память** выгружают все результаты.
- **Удалить** в строке или **Удалить память этой проверки** после подтверждения удаляет её снимок, страницы, исходные карточки и журнал. Общая память пересчитывается по оставшимся проверкам: их строки и независимые импорты сохраняются, исчезают только строки удалённой проверки. Другие вкладки расширения обновляются автоматически.
- **Удалить всю память** удаляет все проверки, товары, исходные карточки, журналы, настройки и образцы сайтов. Отмена подтверждения ничего не меняет. Файлы ранее скачанных выгрузок не удаляются.

Удаление доступно после паузы выполняемого задания и окончания остановки. Удалённое текущее задание больше нельзя продолжить; перезапуск фона не восстанавливает его. Настройки и образцы сайта сохраняются при удалении одной проверки.

Импортированные отдельно товары хранятся как независимая память и не удаляются вместе с проверкой, даже если тот же товар встретился в ней. Для удаления импортированных данных используйте очистку всей памяти. При переходе с 0.5 сохраняются записанные задания. Для старых данных без истории нельзя восстановить происхождение полей, уже смешанных с импортом, или отнести исходные карточки без ID задания к конкретной проверке; такие неразмеченные исходники остаются до полной очистки.

## Задания и накопительная память

1. Откройте нужную выдачу на сайте. Укажите название задания / метку поиска, число страниц и нажмите **Запустить задание**.
2. Следите за текущим этапом, числом сохранённых страниц, найденными товарами и журналом. **Пауза → Продолжить** сохраняет то же задание, в том числе при капче. Одновременно выполняется одно задание; очереди поисковых запросов пока нет.
3. Для следующего наименования выполните новый поиск на сайте, укажите новую метку и запустите новое задание. Результаты предыдущих заданий останутся в памяти.
4. В **Истории заданий** видны дата, площадка, состояние, страницы и количество товаров. В списке **Показать результаты** можно выбрать снимок конкретного задания или **Всю память**.
5. Нажмите **Скачать JSON** или **Excel (.xlsx)**. Эти кнопки в основном окне включают все накопленные задания, независимо от выбранного фильтра. Во вкладке истории есть отдельные кнопки экспорта выбранной проверки.
6. **Обнулить память** после подтверждения удаляет товары, исходные карточки, задания, журналы, настройки и образцы сайтов. Сначала приостановите выполняемое задание и дождитесь остановки. Сохранённые на компьютере файлы и выданные через Chrome разрешения сайтов остаются у вас.

Память хранится в `chrome.storage.local` в текущем профиле браузера и переживает закрытие интерфейса, перезапуск фонового процесса и обновление той же установленной копии расширения. Удаление расширения или данных его профиля может удалить память; для резервной копии сохраняйте JSON. Автоматическая облачная синхронизация не используется.

У каждого задания собственные товары, страницы, журнал и состояние. Последующие поиски не переписывают его снимок. Общая память сохраняет отдельные появления карточек. Каждая новая строка связана со своим заданием через `task_id` и `task_ids`; одинаковый `source + product_id` не объединяет строки. Если цена изменилась в новом задании, прежняя цена остаётся в снимке старого задания. Процент прогресса относится к заданному лимиту страниц, а не ко всем товарам маркетплейса; если выдача закончилась раньше лимита, задание завершено с фактическим числом страниц. При запуске нового задания прежнее приостановленное задание архивируется как остановленное и больше не продолжается.

В Excel четыре листа: **Товары** (общая память), **Поставщики**, **Задания**, **Товары заданий** (отдельные наблюдения каждого поиска). ID и собранные значения сохраняются текстом, отсутствующие поля — пустыми ячейками, даты — ISO 8601 UTC. Текст не исполняется как формула. `.xlsx` создаётся полностью локально, без внешнего сервиса или библиотеки из CDN. Действуют ограничения Excel: 1 048 576 строк на лист и 32 767 символов в ячейке; слишком длинный текст обрезается в Excel, полный текст остаётся в JSON.

Новые задания собирают только выдачу. Анализ нескольких выгрузок, отбор карточек для дополнительного обхода и новая аналитика в этой версии не добавлены. Прежняя ручная проверка карточек доступна отдельно в **Дополнительных инструментах** и сама не запускается.

При обновлении с 0.4 существующие товары сохраняются; из старого состояния доступно только последнее задание. Историю более ранних заданий прежняя версия не записывала. **Импорт JSON** переносит товары и доступные исходные карточки; восстановление истории заданий из импортируемого файла пока не поддерживается. Экспортированные снимки заданий доступны непосредственно в JSON и Excel.

## Возможности движка

- Навигация определяется по нескольким признакам: подписи и доступные имена кнопок, `rel=next`, контекст пагинации, номера страниц, изменения URL, стрелки и кнопки догрузки.
- Поддерживаются кликабельные `div` и `span`, включая пустой `div.fui-next` в присланной разметке 1688. Доступная подпись `Go to next page` Alibaba тоже распознаётся.
- Ссылки `target="_blank"` открываются в рабочей вкладке. Вкладки, открытые JavaScript, отслеживаются по связи с исходной вкладкой или известному адресу перехода. Продолжение подтверждается изменением выдачи или доказательством перехода на следующую страницу; повторные товары допускаются.
- Для неизвестных сайтов добавлен общий анализ повторяющейся структуры карточек, семантических атрибутов и JSON-LD. Изменение имён CSS-классов само по себе не меняет ID товара.
- Если вариант перехода неоднозначен, задание приостанавливается. Можно выбрать предложенную кнопку, указать образец на странице или продолжить в выбранной вкладке.
- Образцы карточки и кнопки сохраняются отдельно для каждого сайта. В интерфейсе видны причины выбора и оценка алгоритма.

Это локальный алгоритм с несколькими источниками данных и настройкой по образцу. Оценка `/100` — сила найденных признаков, а не вероятность правильности. Внешняя модель ИИ, ключ ChatGPT и отдельный сервер не используются.

## Дополнительные методы версии 0.4

| Метод | До 0.4 | Теперь |
| --- | --- | --- |
| JSON-LD и ссылки на товары | Поддерживались | Сохранены; более слабые признаки не затирают их поля в одном проходе |
| Microdata, RDFa, h-product | Частичное чтение DOM | Отдельные источники со строгой принадлежностью полей товару и продавцу |
| JSON состояния внутри скриптов и атрибутов | Только JSON-скрипты | Читаются чистые JSON-присваивания и `data-props`/`data-product` без исполнения JavaScript |
| Состояние React/Vue и корневые данные приложения | Не читались | Ограниченный просмотр собственных полей без вызова getters; возвращаются только товарные поля |
| Карточки с разными родителями | Повторяющиеся соседние блоки | Добавлены поиск контейнера вокруг товарной ссылки и сравнение структуры/расположения |
| Доступные имена и изображения | Основные подписи и `img` | Добавлены `aria-labelledby`, `role=heading`, `srcset`, SVG- и CSS-стрелки |
| Формы пагинации и данные следующей страницы | Не поддерживались | Поле/список номера страницы, ограничение последней страницы, явный `nextPageUrl` |
| Динамическая выдача | Прокрутка и опрос | MutationObserver удерживает кратковременные карточки; прокручиваются также внутренние контейнеры |
| iframe | Не поддерживались | Читается доступная разметка того же origin; навигация разрешается в документе iframe |
| Уже загруженные JSON-ответы | Не читались | Опциональное наблюдение за `fetch`/XHR с возвратом только товарных полей |

Методы дополняют сведения одной карточки, а источник каждого поля сохраняется. В отдельной строке наблюдения показанные на её DOM-карточке значения сохраняются отдельно от других появлений того же ID. Отдельные записи без ссылки связываются с видимой карточкой только по уникальному совпадению явного ID. Если одному ID соответствуют несколько ссылок на варианты, автоматическое связывание не выполняется. Расхождение цен источников отмечается в диагностике; для данных без DOM при равной полноте выбирается источник с большей оценкой извлечения. Это не подтверждение актуальности цены.

**Дополнять данные из ответов сайта** выключено по умолчанию. Включайте его, когда обычный сбор даёт неполные данные. Наблюдатель читает JSON, который сайт уже запросил; дополнительных запросов не делает и исходный ответ приложению не заменяет. Он регистрируется для следующих загрузок страницы, включается для вкладок задания и выключается при паузе/завершении. В этом режиме функции `fetch`/XHR страницы оборачиваются; совместимость такой интеграции требует проверки на конкретном сайте. При проблемах отключите режим и обновите вкладку.

Просмотр данных ограничен временем, числом объектов и размером ответа. Полные состояния приложения, заголовки, cookies и тела сетевых ответов в файл не записываются. Известные поля авторизации и входа исключаются. Большие/нестандартные ответы могут быть пропущены; об ограничении сообщается предупреждением. Данные ответа могут включать рекомендации, поэтому перед большим сбором сверяйте выборку с нужной выдачей.

Локальный OCR, нейросетевое распознавание снимков, доступ к закрытому Shadow DOM и управление через Chrome Debugger **не внедрены**. У режима без внешней модели нет универсального способа восстановить скрытый URL или ID из одних пикселей. Карточки в canvas могут извлекаться из доступных данных приложения/JSON-ответов, но элементы, доступные только как изображение, требуют ручного действия или отдельного визуального движка.

## Установка или обновление

1. Скачайте [supplier-viewer-0.16.0.zip](https://github.com/teplydom12-boop/1688Viewer/raw/refs/heads/main/releases/supplier-viewer-0.16.0.zip) из GitHub и распакуйте архив.
2. Откройте `chrome://extensions`, включите **Режим разработчика**.
3. Нажмите **Загрузить распакованное расширение**, выберите папку `supplier-viewer` с `manifest.json`.
4. Для обновления установленной копии замените файлы в её папке, нажмите кнопку обновления расширения и обновите открытые вкладки сайтов.
5. Для установки из GitHub: **Code → Download ZIP**, распакуйте проект и загрузите папку **extension** внутри него.

При установке новой копии отдельно от старой сначала экспортируйте данные из старой, отключите её и импортируйте JSON в новой версии. Автоматического переноса между разными идентификаторами расширений нет.

Для трёх исходных маркетплейсов доступ объявлен при установке. Для остальных сайтов Chrome запрашивает доступ **к выбранному домену** при запуске сбора, поиске кнопок или выборе образца. Если переход ведёт на другой домен, работа останавливается до выдачи доступа. Разрешение `tabs` нужно для списка вкладок и отслеживания продолжения выдачи; расширение обрабатывает вкладки задания, а не автоматически собирает все открытые сайты. Политика управляемого Chrome может запрещать установку.

## Первый запуск

1. Откройте сайт, выполните поиск по тексту или фото.
2. Нажмите расширение → **Открыть задания и накопленные результаты**.
3. Выберите вкладку с выдачей. Для проверки оставьте **1 страницу** и паузу **3 секунды**.
4. Нажмите **Запустить задание** и разрешите доступ к сайту, если Chrome его запросит.
5. Сравните несколько товаров, цен и ссылок с сайтом. Для эвристически определённых карточек интерфейс показывает оценку извлечения.
6. Для нескольких страниц увеличьте лимит. При необходимости сначала нажмите **Определить навигацию** и проверьте выбранную кнопку.
7. Сохраните JSON или Excel (.xlsx). JSON содержит историю заданий, поставщиков с деревом товаров и плоский массив `products`; CSV также сохранён как дополнительный формат.

Метка поиска необязательна. Для фотографии можно указать «Фото №1». Изображение загружается средствами сайта; расширение использует готовую выдачу.

## Если сайт устроен необычно

**Не найдены товары.** Поставьте задание на паузу, выберите нужную вкладку и нажмите **Указать карточку на странице**. На сайте нажмите название или изображение одного товара. Расширение выделит контейнер карточки и сохранит образец. Затем продолжите сбор. Esc отменяет выбор. Одиночную карточку можно указать, если её название, изображение и цена доступны в DOM.

**Не найдена кнопка или найдено несколько вариантов.** Нажмите **Определить навигацию**. Для каждого кандидата показаны подпись, причины оценки и признак новой вкладки. Выберите **Использовать**, затем **Продолжить**. Если нужной кнопки в списке нет, нажмите **Указать кнопку перелистывания** и выберите её на сайте. Этот выбор сохраняется для следующих сборов на том же сайте.

**Открылась другая вкладка.** При однозначном результате расширение продолжает автоматически. Если несколько вкладок подходят или браузер не сообщил связь между ними, обновите список вкладок, выберите нужную и нажмите **Продолжить в выбранной вкладке**. Перейти к следующим товарам вручную тоже можно. Неизменившаяся выдача не засчитывается как новая страница.

**Выдача закончилась, но сайт не показывает отключённую кнопку.** Нажмите **Выдача закончилась** в приостановленном задании. Собранные данные и задание сохранятся в истории.

**После редизайна сохранённый образец больше не подходит.** Нажмите **Сбросить образцы этого сайта**, снова определите навигацию или укажите образцы.

## Магазины и проверка страниц товаров

Имя магазина нельзя получить из выдачи, если сайт его там не публикует. Используйте **Этап 2, поиск поставщиков**: выберите задания, обработайте сохранённые сведения и при необходимости запустите очередь карточек. В новых заданиях сбора выдачи этот этап не запускается автоматически. Во время проверки не меняйте адрес рабочей вкладки.

Если несколько товаров связаны надёжным ID поставщика, для поиска магазина достаточно одной его карточки. При известной ссылке на магазин открытие не требуется. Цены и характеристики соседних товаров не копируются. Товары без доступной ссылки на карточку автоматически не проверяются и остаются в результате.

Файлы выдачи версий 0.1–0.16 можно импортировать через **Импорт JSON**. Импорт добавляет независимые строки в память и не восстанавливает задания истории; выбор этапа 2 пока основан именно на сохранённых заданиях. Бренд, рейтинг и процент повторных заказов не принимаются за название продавца. Неподтверждённые поля исходных карточек остаются пустыми; в таблице этапа 2 используется пометка «Поставщик неизвестен».

На ранее присланных пользователем сохранённых страницах версии 0.2 восстановлены 59 товаров текстового поиска и 60 товаров поиска по фото с 32 идентификаторами поставщиков. Имена магазинов в этих снимках отсутствовали. Пользовательские HTML и JSON не включены в репозиторий; в тестах используются обезличенные примеры.

## Управление и границы автоматизации

В интерфейсе видны этап, число страниц, очередь карточек, прогресс и журнал последних 100 действий. **Пауза** сохраняет уже прочитанные карточки, включая данные при прерывании прокрутки. **Продолжить** возобновляет сохранённый этап; перед этим можно изменить паузу между переходами. **Рабочая вкладка** открывает обрабатываемую страницу.

Капча, форма входа, ограничение частоты запросов, неподтверждённый переход, неоднозначная навигация или отсутствие изменений после нажатия останавливают задание. Проверку безопасности выполняет пользователь. Повторных кликов в бесконечном цикле и автоматического решения капчи нет.

Один запуск обрабатывает 1–20 страниц с паузой 1–30 секунд. Прокрутка и ожидание загрузки ограничены; неполнота отмечается предупреждением. Умеренный темп снижает нагрузку, но не гарантирует отсутствие капч и не имитирует человеческое поведение для обхода защиты.

Работа **на абсолютно любом сайте после любого редизайна не гарантируется**. Общий движок уверенно распознаёт не все структуры. Например:

- Закрытый Shadow DOM, карточки в canvas или в iframe другого origin не доступны текущему анализу DOM. Открытый Shadow DOM и доступные iframe того же origin поддерживаются.
- Сайт может блокировать программные клики или открытие окон без действия пользователя. Для таких переходов нужен ручной переход или настройка разрешений браузера.
- На странице без товарных признаков, цены, структурированных данных или повторяющихся карточек может понадобиться образец. Для автоматического анализа неизвестной структуры приоритет отдаётся точности: непохожие блоки и карточки без цены могут быть пропущены.
- Ссылка с неизвестной схемой маршрутов может оказаться неверной; перед большим сбором проверяйте несколько строк. Поля из структурированных данных имеют приоритет перед более слабыми признаками того же прохода.
- Локальный образец не переносится автоматически между доменами и может потребовать повторного выбора после изменения структуры.

## Продолжение после капчи

При видимой проверке безопасности или явном ответе API, требующем капчу, задание приостанавливается. В popup есть **Открыть рабочую вкладку / капчу**. Пройдите проверку на сайте вручную и нажмите **Продолжить** один раз. Повторный запуск сбора или повторный импорт не нужен.

Кнопка проверяет, исчезла ли капча. Если проверка ещё видна, задание остаётся на паузе и переход не повторяется. Если капча остановила переход на прежнем адресе, программа после её решения проверяет товары и повторяет переход один раз. Если следующая выдача уже появилась, она собирается сразу. Контрольная точка сохраняется и после перезапуска фонового процесса.

Для текстового поиска на исходных маркетплейсах, если после капчи данные доступны только через ответы сайта и новых товаров нет, включённый режим наблюдения может заново открыть тот же поисковый адрес один раз. URL с запросом сохраняется. Для поисков, параметры которых существуют только в памяти страницы, автоматическое восстановление после полной перезагрузки не гарантируется.

Капча не решается автоматически, проверки сайта не обходятся. Вкладки, формы и серверы могут вести себя иначе после редизайна; при неподтверждённом переходе программа сохраняет данные и запрашивает ручной выбор.

## Поставщики и идентификаторы

Поставщики объединяются по **ID магазина или канонической ссылке** в пределах площадки. Одинаковое название или фотография не объединяют компании автоматически. Под поставщиком показаны товары текущих сборов, а не весь ассортимент компании. Неопределённые поставщики остаются отдельными товарами.

Для трёх маркетплейсов сохраняются их ID предложений. На других сайтах источник имеет вид `web:example.com`, а ID обычно вычисляется по канонической ссылке. Трекинговые параметры удаляются; параметры вариантов товара сохраняются. Это локальный ID расширения, а не официальный ID сайта.

Если ссылки нет, используются явный `data-product-id`/SKU либо отпечаток названия, изображения и цены. Такие записи помечаются `native-id` или `card-fingerprint`, ссылка остаётся `null`. Отпечаток без официального ID может измениться при изменении цены или названия; точное удаление дублей таких карточек не гарантируется.

## Исходные карточки и JSON

С включённым сохранением исходников сохраняется очищенная разметка найденных карточек с их ID и адресом выдачи. Скрипты, формы, поля ввода, обработчики событий и посторонние атрибуты удаляются. Полные страницы, cookies, полные тела сетевых ответов и данные входа не сохраняются. Для источников без DOM снимок содержит нормализованный товарный `record` вместо разметки. Карточки больше 20 000 символов сохраняются только в нормализованном виде.

**Сырой JSON** добавляет `raw_cards`: очищенный HTML или нормализованный товарный `record` для источника без DOM. **Переразобрать карточки** применяет текущий движок к этим снимкам без новой загрузки сайта. Снимок не восстановит сведения, которых в нём не было, включая отсутствующее имя магазина.

Схема экспорта — **3**. Поля верхнего уровня: `collection_mode`, `sources`, `exported_at`, `total_products`, `total_suppliers`, `total_tasks`, `tasks`, `pages`, `suppliers`, `unresolved_products`, `products`; в сыром экспорте также `raw_cards`.

Строка наблюдения дополнительно содержит `observation_id`, `task_id`, `checkpoint_id`, `page_index`, `card_index`, `page_card_key`, `capture_status`. Товар содержит `source`, `product_id`, `title`, `product_url`, `supplier_id`, `shop_name`, `supplier_url`, `price`, `minimum_order`, `image_url`, `query`, `search_type`, `collected_at`, `last_seen_at`, `source_page_url`, `sightings`, `task_ids`, `field_sources`, `field_confidence`, `identity_type`, `extraction_confidence`; при расхождении цен — `data_conflicts`; после проверки может появиться `detail_checked_at`. ID — строки, даты — ISO 8601 UTC, цена и минимальный заказ — строки без угадывания валюты и единиц. Отсутствующие значения — `null`. CSV защищает значения от интерпретации как формулы Excel.

Результаты и образцы хранятся локально в браузере; на внешний сервер они не отправляются. Переходы и догрузка используют обычную работу сайта.

## Разработка и проверка

Для установки нужен Chrome 111+. Для разработки нужны Node.js 22+, Python 3 для архива и Chromium для браузерных тестов. По умолчанию браузер — `/usr/bin/chromium`; другой путь задаётся через `CHROMIUM_PATH`.

```bash
cd /workspace/1688Viewer
npm ci --cache /tmp/1688viewer-npm-cache --ignore-scripts --no-audit --no-fund

```

Архив: `dist/supplier-viewer-0.16.0.zip`. В него не входят зависимости, тесты, пользовательские файлы и данные сборов.

Тесты этапа 2 проверяют выбор нескольких площадок, сохранность исходных появлений, кэш подтверждённых продавцов, отсутствие перехода при известном магазине, интервал и его восстановление после перезапуска, капчу/продолжение на трёх площадках, пропуск незавершённой проверки, неизвестных продавцов, отделение рекомендаций, доступ к сторонним доменам, остановку при закрытии вкладки, запрет одновременной работы этапов, очистку зависимых результатов, JSON/CSV/XLSX и интерфейс дерева с настройками картинок. Отдельный тест воспроизводит задержанное обновление продавца при смене fragment-маршрута SPA: очередь использует новый документ без дополнительного запроса к площадке, чтобы не перенести прежнего продавца.

Тесты проверяют отдельные появления повторных ID с разными ценами, несколько страниц/заданий, полностью повторную следующую страницу, SPA-переход, догрузку дубликата, паузу/перезапуск/продолжение без технических копий, импорт/переразбор повторных строк и сохранность JSON/CSV/Excel. Проверены контролируемые страницы 1688, Alibaba и Made-in-China. Дополнительно проверяется показ/скрытие миниатюр, сохранение режима истории, ошибки изображений, разрешения на серверы картинок, отмену подготовки, экспорт без загрузки картинок и настоящий XLSX со встроенными JPEG, общими медиафайлами и привязкой рисунков к ячейкам. Структура файла и миниатюры дополнительно проверены независимым считывателем openpyxl; настольного Excel в облаке нет, нажатия + / − в нём здесь не проверялись. Тесты также проверяют отдельную вкладку истории, удаление одной и всех проверок, сохранность общих и импортированных товаров, восстановление полей, запрет удаления во время выполнения/продолжения, выборочный экспорт и обновления между вкладками. Тесты проверяют реальный DOM и интерфейс в Chromium: три маркетплейса, неизвестные структуры, изменение классов, Shadow DOM, JSON-LD, варианты товаров, пустые ссылки, повторный анализ, пагинацию, догрузку, новые вкладки, неоднозначный выбор, обучение по образцу, доступ к доменам, сохранение, обогащение, капчу и экспорт. Chrome API в интеграционных тестах моделируется. Полный цикл капчи и продолжения кнопкой popup проверяется отдельно для 1688, Alibaba и Made-in-China на контролируемых страницах с изменением разметки и перезапуском фона. Фикстуры не являются живыми страницами площадок.

```bash

```

В облачном Chromium установка запрещена управляемой политикой `ExtensionInstallBlocklist: ["*"]`; эта проверка заблокирована. Политики не изменяются. Живые страницы трёх маркетплейсов и нативная работа расширения в пользовательском Chrome здесь не проверены: облачный прокси отклоняет соединения с HTTP 403. Доступ к доменам сохранён в сетевом черновике; сохранение черновика не применяет сетевую политику автоматически. Снимки и тестовые страницы не подтверждают совместимость всех текущих страниц сайтов.
