# Supplier Viewer 0.9

[Скачать готовое расширение 0.9.0 (.zip)](https://github.com/teplydom12-boop/1688Viewer/raw/refs/heads/main/releases/supplier-viewer-0.9.0.zip)

Расширение Chrome для сбора товаров и поиска поставщиков на **1688, Alibaba, Made-in-China и других сайтах с карточками товаров**. Вы выполняете поиск по тексту или фото средствами сайта. Расширение собирает выдачу, продолжает её через страницы или догрузку, сохраняет задания в общей памяти и показывает **таблицу поставщиков с деревом найденных товаров**.

## Сбор без удаления дублей — версия 0.9

Каждая распознанная карточка сохраняется отдельной строкой, даже если ID товара и ссылка уже встречались на этой странице, на других страницах или в прошлых заданиях. Разные цены, минимальные заказы и прочие показанные поля у повторных карточек не заменяют друг друга. Счётчики, история, таблица поставщиков и JSON / CSV / Excel учитывают все строки. Например, две подтверждённые страницы по 60 карточек дают 120 записей, даже если часть товаров повторяется. Фильтрация и удаление дублей остаются следующим этапом и автоматически не выполняются.

Новые записи содержат **ID записи** (`observation_id`), **ID задания** (`task_id`), **страницу задания** (`page_index`), **позицию карточки** (`card_index`), адрес выдачи, запрос, дату и **статус записи** (`capture_status`). Статус `confirmed` означает сохранённую страницу, `partial` — незавершённую контрольную точку, `imported` — строку из импортированного файла. Эти поля добавлены в JSON и отдельными колонками в Excel / CSV. `product_id` по-прежнему обозначает предложение и может повторяться; `observation_id` обозначает конкретную сохранённую строку. Позиция соответствует порядку распознавания и может отличаться от визуального порядка при сборе из данных приложения.

Техническое перечитывание той же карточки во время прокрутки, загрузки полей или продолжения после паузы обновляет её строку в текущей контрольной точке. Успешное продолжение заменяет незавершённый снимок страницы и сохраняет ID уже известных позиций. При «Загрузить ещё» сохраняются вновь добавленные позиции, включая карточки с уже известным ID; старые позиции остающегося на экране списка не копируются повторно. Распознавание из DOM, JSON-LD, данных приложения и ответов объединяет представления одной карточки, но сохраняет повторные карточки в списке. Если сайт виртуализирует полностью одинаковые карточки и не даёт ни позиции, ни других отличимых признаков, точно различить их отдельные появления невозможно.

Переход может подтверждаться номером показанной страницы, новым документом по другому адресу или изменившимся содержимым карточек после нажатия. Новый ID товара больше не является обязательным условием: следующая страница может целиком состоять из повторов. При неизменной странице кнопка не нажимается в цикле. Неоднозначность, несовпадение номера страницы и признаки незавершённой загрузки по-прежнему вызывают паузу. Уже увиденные карточки сохраняются как `partial` вместе с диагностикой; неподтверждённая страница не увеличивает прогресс. Капча и продолжение одной кнопкой сохранены.

Импорт сохраняет все строки файла, включая одинаковые строки и повторный импорт того же файла. Каждому импорту назначается свой `import_batch_id`, строкам — новые `observation_id`; исходные ID записи и задания доступны как `imported_observation_id` и `imported_task_id`. История заданий из файла по-прежнему не импортируется. Удаление проверки удаляет только её наблюдения; строки остальных проверок и независимых импортов сохраняются. Переразбор исходников сохраняет повторные записи, а его импорт добавляет новую порцию в память.

Существующая память сохраняется без сброса. Повторы, уже объединённые прежними версиями, автоматически не восстанавливаются: для полного исходного набора нужен новый сбор. Старые строки могут не содержать новых полей происхождения. Схема JSON остаётся **3**, добавлен маркер `collection_mode: "all_cards"`.

## Картинки в Excel и истории — версия 0.8

В истории откройте память проверки и нажмите **Показать картинки**. Миниатюры 48 × 48 пикселей появляются в колонке «Изображение»; кнопка меняется на **Скрыть картинки**. Выбор сохраняется между вкладками и перезапусками браузера. По умолчанию картинки скрыты и не загружаются. Скрытие возвращает компактные ссылки; недоступная картинка оставляет ссылку с пометкой. Удаление одной проверки сохраняет настройку, очистка всей памяти сбрасывает её.

Кнопка **Excel** в popup, основной таблице или истории открывает экран подготовки экспорта. Галочка **Включить компактные картинки в файл** включена по умолчанию. Нажмите **Сохранить Excel**: Chrome при необходимости запросит доступ только к адресам серверов изображений из выбранной выгрузки. Затем появится прогресс загрузки с количеством успешных и недоступных изображений. Подготовку можно отменить. Без галочки файл сохраняется сразу со ссылками на картинки, разрешения на серверы изображений не запрашиваются.

На листах **Товары** и **Товары заданий** миниатюры расположены в отдельном узком столбце, целиком в границах ячеек. В **Excel 2016 / 2019 / 2021** нажмите стандартный **− над столбцом фото**, чтобы скрыть его вместе с изображениями, или **+**, чтобы вернуть. На каждом из двух листов свой переключатель. Если символы структуры отключены в настройках Excel, включите «Показывать символы структуры, если структура применена» в параметрах отображения листа. Строки имеют компактную высоту 36 пунктов; скрытие столбца не меняет высоту строк.

Используются обычные встроенные рисунки Excel с привязкой «перемещать и изменять размер вместе с ячейками». Это совместимый со старыми версиями способ размещения внутри границ ячейки, а не новый тип ячейки `IMAGE()`. Макросы, формулы для изображений и внешние связи в файле не нужны. Копии изображений хранятся в `.xlsx` и после экспорта доступны без Интернета. Первичная загрузка требует доступа к серверу картинок. Ссылки на оригиналы сохраняются отдельным текстовым полем.

Обработка выполняется локально в браузере: до четырёх загрузок одновременно, 8 секунд на загрузку, предел исходного файла 8 МБ и 40 миллионов пикселей, уменьшение до JPEG 96 × 96 с сохранением пропорций. Одинаковая ссылка загружается и встраивается один раз, даже если товар есть в нескольких проверках. Общий предел миниатюр — 32 МБ. Недоступные, перенаправляемые и слишком большие изображения пропускаются с пометкой «Нет миниатюры»; товары и исходные ссылки сохраняются. Данные не отправляются в AI-сервисы. Разрешения Chrome на серверы изображений можно отозвать в настройках расширения.

## Проверка полноты выдачи в версии 0.7

Сбор дожидается появления новой выдачи, прежде чем включить накопление карточек наблюдателем. После перехода проверяются все ID ранее подтверждённых страниц задания, а не только предыдущая страница. Если есть свежие DOM-карточки, старые записи из состояния приложения без соответствующей DOM-карточки не подмешиваются к новой выдаче.

Перед сохранением проверяются количество найденных, новых и повторных ID. Явный номер страницы в URL сопоставляется с номером загруженных карточек (`page_num` на 1688) или доступным индикатором текущей страницы. Несовпадение либо смешение номеров означает, что переход ещё не подтверждён; URL без явного номера не трактуется как первая страница. Выдача из большого числа старых товаров и одного нового не считается успешной страницей. При включённой прокрутке размер страницы из явных атрибутов/параметров или предыдущей подтверждённой страницы служит ориентиром: сильное недозаполнение вызывает ожидание и паузу. Настройка `page_size@60` из карточек 1688 также распознаётся. Маленькая последняя страница с подтверждённо отключённым переходом допускается. Явная кнопка «Load more / Загрузить ещё» на том же адресе учитывается как дополнение списка: наличие старых карточек в таком режиме ожидаемо и не вызывает ложную паузу. Это проверка по признакам, а не гарантия фиксированного числа товаров на любом сайте.

При неподтверждённой полноте задание получает состояние **Пауза**, страница не засчитывается, а все увиденные карточки сохраняются отдельными частичными строками. Строки подтверждённых страниц не изменяются. При несовпадении номеров сохраняются частичный снимок и диагностика; такой снимок нельзя считать подтверждённой страницей. Дождитесь загрузки или обновите выдачу на том же адресе, затем нажмите **Продолжить**. Сохранённая часть заменяется полной контрольной точкой, когда сбор подтверждён. Диагностика `collection_quality` содержит ожидаемое и фактическое количество, новые/повторные ID и признак последней страницы. Новые ID здесь считаются относительно уже подтверждённых страниц, без частичного результата текущей страницы.

В popup крупные счётчики и список товаров относятся к текущему заданию и начинают с нуля при новом запуске. Общая память сохраняется; её размер указан отдельно. Кнопки popup **Вся память: JSON / Excel** выгружают все задания, а выбранную проверку можно выгрузить из истории.

На всех листах Excel есть колонка **Сайт-источник**, например `1688.com`, `alibaba.com` или `made-in-china.com`. На листах товаров также есть **Адрес сайта-источника** с фактическим origin выдачи и **Страница выдачи** с её полным адресом. JSON сохраняет прежние коды `source`.

У изображений исключены флаги стран, маленькие служебные иконки и известные заглушки. Ссылки на товар Made-in-China больше не интерпретируются как ссылки на магазин. Границы глубоко вложенной карточки учитывают соседние ID, а скрипты/шаблоны не участвуют в определении текста и размера карточки.

Уникальные товары и число наблюдений на страницах различаются: один товар может повторяться в выдаче. Проверка не обещает 600 уникальных предложений при 10 страницах по 60 карточек. Сохранённый HTML виртуализированной выдачи может содержать только видимую часть, например 15 карточек; отсутствующие карточки из такого снимка восстановить нельзя. Пользовательские отчёты не входят в репозиторий или установочный архив.

## История проверок в версии 0.6

Откройте **История проверок ↗** из popup расширения или шапки основной таблицы. История открывается в отдельной вкладке браузера и показывает все записанные задания: название, дату, площадку, состояние, страницы и количество товаров. Доступен поиск по названию, площадке и состоянию.

- **Открыть память** показывает снимок конкретной проверки: товары, цены, минимальный заказ, магазины, ссылки, изображения, даты, сохранённые страницы и журнал. Фрагмент адреса сохраняет выбранную проверку, поэтому её можно открыть снова после перезагрузки вкладки. Данные выполняемого задания обновляются автоматически.
- **JSON этой проверки**, **Excel этой проверки** и **Исходники этой проверки** выгружают только выбранное задание. Верхние кнопки **Вся память** выгружают все результаты.
- **Удалить** в строке или **Удалить память этой проверки** после подтверждения удаляет её снимок, страницы, исходные карточки и журнал. Общая память пересчитывается по оставшимся проверкам: их строки и независимые импорты сохраняются, исчезают только строки удалённой проверки. Другие вкладки расширения обновляются автоматически.
- **Удалить всю память** удаляет все проверки, товары, исходные карточки, журналы, настройки и образцы сайтов. Отмена подтверждения ничего не меняет. Файлы ранее скачанных выгрузок не удаляются.

Удаление доступно после паузы выполняемого задания и окончания остановки. Удалённое текущее задание больше нельзя продолжить; перезапуск фона не восстанавливает его. Настройки и образцы сайта сохраняются при удалении одной проверки.

Импортированные отдельно товары хранятся как независимая память и не удаляются вместе с проверкой, даже если тот же товар встретился в ней. Для удаления импортированных данных используйте очистку всей памяти. При переходе с 0.5 сохраняются записанные задания. Для старых данных без истории нельзя восстановить происхождение полей, уже смешанных с импортом, или отнести исходные карточки без ID задания к конкретной проверке; такие неразмеченные исходники остаются до полной очистки.

## Задания и накопительная память

1. Откройте нужную выдачу на сайте. Укажите название задания / метку поиска, число страниц и нажмите **Запустить задание**.
2. Следите за текущим этапом, числом сохранённых страниц, найденными товарами и журналом. **Пауза → Продолжить** сохраняет то же задание, в том числе при капче. Одновременно выполняется одно задание; очереди поисковых запросов пока нет.
3. Для следующего наименования выполните новый поиск на сайте, укажите новую метку и запустите новое задание. Результаты предыдущих заданий останутся в памяти.
4. В **Истории заданий** видны дата, площадка, состояние, страницы и количество товаров. В списке **Показать результаты** можно выбрать снимок конкретного задания или **Всю память**.
5. Нажмите **Скачать JSON** или **Excel (.xlsx)**. Эти кнопки в основном окне включают все накопленные задания, независимо от выбранного фильтра. Во вкладке истории есть отдельные кнопки экспорта выбранной проверки.
6. **Обнулить память** после подтверждения удаляет товары, исходные карточки, задания, журналы, настройки и образцы сайтов. Сначала приостановите выполняемое задание и дождитесь остановки. Сохранённые на компьютере файлы и выданные через Chrome разрешения сайтов остаются у вас.

Память хранится в `chrome.storage.local` в текущем профиле браузера и переживает закрытие интерфейса, перезапуск фонового процесса и обновление той же установленной копии расширения. Удаление расширения или данных его профиля может удалить память; для резервной копии сохраняйте JSON. Автоматическая облачная синхронизация не используется.

У каждого задания собственные товары, страницы, журнал и состояние. Последующие поиски не переписывают его снимок. Общая память сохраняет отдельные появления карточек. Каждая новая строка связана со своим заданием через `task_id` и `task_ids`; одинаковый `source + product_id` не объединяет строки. Если цена изменилась в новом задании, прежняя цена остаётся в снимке старого задания. Процент прогресса относится к заданному лимиту страниц, а не ко всем товарам маркетплейса; если выдача закончилась раньше лимита, задание завершено с фактическим числом страниц. При запуске нового задания прежнее приостановленное задание архивируется как остановленное и больше не продолжается.

В Excel четыре листа: **Товары** (общая память), **Поставщики**, **Задания**, **Товары заданий** (отдельные наблюдения каждого поиска). ID и собранные значения сохраняются текстом, отсутствующие поля — пустыми ячейками, даты — ISO 8601 UTC. Текст не исполняется как формула. `.xlsx` создаётся полностью локально, без внешнего сервиса или библиотеки из CDN. Действуют ограничения Excel: 1 048 576 строк на лист и 32 767 символов в ячейке; слишком длинный текст обрезается в Excel, полный текст остаётся в JSON.

Новые задания собирают только выдачу. Анализ нескольких выгрузок, отбор карточек для дополнительного обхода и новая аналитика в этой версии не добавлены. Прежняя ручная проверка карточек доступна отдельно в **Дополнительных инструментах** и сама не запускается.

При обновлении с 0.4 существующие товары сохраняются; из старого состояния доступно только последнее задание. Историю более ранних заданий прежняя версия не записывала. **Импорт JSON** переносит товары и доступные исходные карточки; восстановление истории заданий из импортируемого файла пока не поддерживается. Экспортированные снимки заданий доступны непосредственно в JSON и Excel.

## Возможности движка

- Навигация определяется по нескольким признакам: подписи и доступные имена кнопок, `rel=next`, контекст пагинации, номера страниц, изменения URL, стрелки и кнопки догрузки.
- Поддерживаются кликабельные `div` и `span`, включая пустой `div.fui-next` в присланной разметке 1688. Доступная подпись `Go to next page` Alibaba тоже распознаётся.
- Ссылки `target="_blank"` открываются в рабочей вкладке. Вкладки, открытые JavaScript, отслеживаются по связи с исходной вкладкой или известному адресу перехода. Продолжение подтверждается изменением выдачи или доказательством перехода на следующую страницу; повторные товары допускаются.
- Для неизвестных сайтов добавлен общий анализ повторяющейся структуры карточек, семантических атрибутов и JSON-LD. Изменение имён CSS-классов само по себе не меняет ID товара.
- Если вариант перехода неоднозначен, задание приостанавливается. Можно выбрать предложенную кнопку, указать образец на странице или продолжить в выбранной вкладке.
- Образцы карточки и кнопки сохраняются отдельно для каждого сайта. В интерфейсе видны причины выбора и оценка алгоритма.

Это локальный алгоритм с несколькими источниками данных и настройкой по образцу. Оценка `/100` — сила найденных признаков, а не вероятность правильности. Внешняя модель ИИ, ключ ChatGPT и отдельный сервер не используются.

| Метод | До 0.4 | Теперь |

| Карточки с разными родителями | Повторяющиеся соседние блоки | Добавлены поиск контейнера вокруг товарной ссылки и сравнение структуры/расположения |

| Динамическая выдача | Прокрутка и опрос | MutationObserver удерживает кратковременные карточки; прокручиваются также внутренние контейнеры |
| iframe | Не поддерживались | Читается доступная разметка того же origin; навигация разрешается в документе iframe |
| Уже загруженные JSON-ответы | Не читались | Опциональное наблюдение за `fetch`/XHR с возвратом только товарных полей |

Методы дополняют сведения одной карточки, а источник каждого поля сохраняется. В отдельной строке наблюдения показанные на её DOM-карточке значения сохраняются отдельно от других появлений того же ID. Отдельные записи без ссылки связываются с видимой карточкой только по уникальному совпадению явного ID. Если одному ID соответствуют несколько ссылок на варианты, автоматическое связывание не выполняется. Расхождение цен источников отмечается в диагностике; для данных без DOM при равной полноте выбирается источник с большей оценкой извлечения. Это не подтверждение актуальности цены.

**Дополнять данные из ответов сайта** выключено по умолчанию. Включайте его, когда обычный сбор даёт неполные данные. Наблюдатель читает JSON, который сайт уже запросил; дополнительных запросов не делает и исходный ответ приложению не заменяет. Он регистрируется для следующих загрузок страницы, включается для вкладок задания и выключается при паузе/завершении. В этом режиме функции `fetch`/XHR страницы оборачиваются; совместимость такой интеграции требует проверки на конкретном сайте. При проблемах отключите режим и обновите вкладку.

Просмотр данных ограничен временем, числом объектов и размером ответа. Полные состояния приложения, заголовки, cookies и тела сетевых ответов в файл не записываются. Известные поля авторизации и входа исключаются. Большие/нестандартные ответы могут быть пропущены; об ограничении сообщается предупреждением. Данные ответа могут включать рекомендации, поэтому перед большим сбором сверяйте выборку с нужной выдачей.

Локальный OCR, нейросетевое распознавание снимков, доступ к закрытому Shadow DOM и управление через Chrome Debugger **не внедрены**. У режима без внешней модели нет универсального способа восстановить скрытый URL или ID из одних пикселей. Карточки в canvas могут извлекаться из доступных данных приложения/JSON-ответов, но элементы, доступные только как изображение, требуют ручного действия или отдельного визуального движка.

## Установка или обновление

1. Скачайте [supplier-viewer-0.9.0.zip](https://github.com/teplydom12-boop/1688Viewer/raw/refs/heads/main/releases/supplier-viewer-0.9.0.zip) из GitHub и распакуйте архив.
2. Откройте `chrome://extensions`, включите **Режим разработчика**.
3. Нажмите **Загрузить распакованное расширение**, выберите папку `supplier-viewer` с `manifest.json`.
4. Для обновления установленной копии замените файлы в её папке, нажмите кнопку обновления расширения и обновите открытые вкладки сайтов.
5. Для установки из GitHub: **Code → Download ZIP**, распакуйте проект и загрузите папку **extension** внутри него.

При установке новой копии отдельно от старой сначала экспортируйте данные из старой, отключите её и импортируйте JSON в новой версии. Автоматического переноса между разными идентификаторами расширений нет.

Для трёх исходных маркетплейсов доступ объявлен при установке. Для остальных сайтов Chrome запрашивает доступ **к выбранному домену** при запуске сбора, поиске кнопок или выборе образца. Если переход ведёт на другой домен, работа останавливается до выдачи доступа. Разрешение `tabs` нужно для списка вкладок и отслеживания продолжения выдачи; расширение обрабатывает вкладки задания, а не автоматически собирает все открытые сайты. Политика управляемого Chrome может запрещать установку.

## Первый запуск

1. Откройте сайт, выполните поиск по тексту или фото.
2. Нажмите расширение → **Открыть задания и накопленные результаты**.
3. Выберите вкладку с выдачей. Для проверки оставьте **1 страницу** и паузу **3 секунды**.
4. Нажмите **Запустить задание** и разрешите доступ к сайту, если Chrome его запросит.
5. Сравните несколько товаров, цен и ссылок с сайтом. Для эвристически определённых карточек интерфейс показывает оценку извлечения.
6. Для нескольких страниц увеличьте лимит. При необходимости сначала нажмите **Определить навигацию** и проверьте выбранную кнопку.
7. Сохраните JSON или Excel (.xlsx). JSON содержит историю заданий, поставщиков с деревом товаров и плоский массив `products`; CSV также сохранён как дополнительный формат.

Метка поиска необязательна. Для фотографии можно указать «Фото №1». Изображение загружается средствами сайта; расширение использует готовую выдачу.

## Если сайт устроен необычно

**Не найдены товары.** Поставьте задание на паузу, выберите нужную вкладку и нажмите **Указать карточку на странице**. На сайте нажмите название или изображение одного товара. Расширение выделит контейнер карточки и сохранит образец. Затем продолжите сбор. Esc отменяет выбор. Одиночную карточку можно указать, если её название, изображение и цена доступны в DOM.

**Не найдена кнопка или найдено несколько вариантов.** Нажмите **Определить навигацию**. Для каждого кандидата показаны подпись, причины оценки и признак новой вкладки. Выберите **Использовать**, затем **Продолжить**. Если нужной кнопки в списке нет, нажмите **Указать кнопку перелистывания** и выберите её на сайте. Этот выбор сохраняется для следующих сборов на том же сайте.

**Открылась другая вкладка.** При однозначном результате расширение продолжает автоматически. Если несколько вкладок подходят или браузер не сообщил связь между ними, обновите список вкладок, выберите нужную и нажмите **Продолжить в выбранной вкладке**. Перейти к следующим товарам вручную тоже можно. Неизменившаяся выдача не засчитывается как новая страница.

**Выдача закончилась, но сайт не показывает отключённую кнопку.** Нажмите **Выдача закончилась** в приостановленном задании. Собранные данные и задание сохранятся в истории.

**После редизайна сохранённый образец больше не подходит.** Нажмите **Сбросить образцы этого сайта**, снова определите навигацию или укажите образцы.

## Магазины и проверка страниц товаров

Имя магазина нельзя получить из выдачи, если сайт его там не публикует. Отдельная кнопка **Дополнительные инструменты → Проверить собранные карточки** открывает страницы товаров в рабочей вкладке. В новых заданиях сбора выдачи этот этап не запускается автоматически. Проверка идёт последовательно с указанной паузой. Во время задания не меняйте адрес рабочей вкладки.

Если несколько товаров уже связаны надёжным ID или URL поставщика, проверяется одна его карточка, а имя и ссылка заполняют недостающие поля связанных товаров. Цены и характеристики соседних товаров не копируются. Товары без доступной ссылки на карточку автоматически не проверяются.

Файлы версий 0.1–0.9 можно импортировать через **Импорт JSON**, затем нажать **Проверить собранные карточки**. Пустые поля не затирают известные значения. Бренд, рейтинг и процент повторных заказов не принимаются за название продавца. Если поставщик не подтверждён, поля остаются пустыми.

На ранее присланных пользователем сохранённых страницах версии 0.2 восстановлены 59 товаров текстового поиска и 60 товаров поиска по фото с 32 идентификаторами поставщиков. Имена магазинов в этих снимках отсутствовали. Пользовательские HTML и JSON не включены в репозиторий; в тестах используются обезличенные примеры.

## Управление и границы автоматизации

В интерфейсе видны этап, число страниц, очередь карточек, прогресс и журнал последних 100 действий. **Пауза** сохраняет уже прочитанные карточки, включая данные при прерывании прокрутки. **Продолжить** возобновляет сохранённый этап; перед этим можно изменить паузу между переходами. **Рабочая вкладка** открывает обрабатываемую страницу.

Капча, форма входа, ограничение частоты запросов, неподтверждённый переход, неоднозначная навигация или отсутствие изменений после нажатия останавливают задание. Проверку безопасности выполняет пользователь. Повторных кликов в бесконечном цикле и автоматического решения капчи нет.

Один запуск обрабатывает 1–20 страниц с паузой 1–30 секунд. Прокрутка и ожидание загрузки ограничены; неполнота отмечается предупреждением. Умеренный темп снижает нагрузку, но не гарантирует отсутствие капч и не имитирует человеческое поведение для обхода защиты.

Работа **на абсолютно любом сайте после любого редизайна не гарантируется**. Общий движок уверенно распознаёт не все структуры. Например:

- Закрытый Shadow DOM, карточки в canvas или в iframe другого origin не доступны текущему анализу DOM. Открытый Shadow DOM и доступные iframe того же origin поддерживаются.
- Сайт может блокировать программные клики или открытие окон без действия пользователя. Для таких переходов нужен ручной переход или настройка разрешений браузера.
- На странице без товарных признаков, цены, структурированных данных или повторяющихся карточек может понадобиться образец. Для автоматического анализа неизвестной структуры приоритет отдаётся точности: непохожие блоки и карточки без цены могут быть пропущены.
- Ссылка с неизвестной схемой маршрутов может оказаться неверной; перед большим сбором проверяйте несколько строк. Поля из структурированных данных имеют приоритет перед более слабыми признаками того же прохода.
- Локальный образец не переносится автоматически между доменами и может потребовать повторного выбора после изменения структуры.

## Продолжение после капчи

При видимой проверке безопасности или явном ответе API, требующем капчу, задание приостанавливается. В popup есть **Открыть рабочую вкладку / капчу**. Пройдите проверку на сайте вручную и нажмите **Продолжить** один раз. Повторный запуск сбора или повторный импорт не нужен.

Кнопка проверяет, исчезла ли капча. Если проверка ещё видна, задание остаётся на паузе и переход не повторяется. Если капча остановила переход на прежнем адресе, программа после её решения проверяет товары и повторяет переход один раз. Если следующая выдача уже появилась, она собирается сразу. Контрольная точка сохраняется и после перезапуска фонового процесса.

Для текстового поиска на исходных маркетплейсах, если после капчи данные доступны только через ответы сайта и новых товаров нет, включённый режим наблюдения может заново открыть тот же поисковый адрес один раз. URL с запросом сохраняется. Для поисков, параметры которых существуют только в памяти страницы, автоматическое восстановление после полной перезагрузки не гарантируется.

Капча не решается автоматически, проверки сайта не обходятся. Вкладки, формы и серверы могут вести себя иначе после редизайна; при неподтверждённом переходе программа сохраняет данные и запрашивает ручной выбор.

## Поставщики и идентификаторы

Поставщики объединяются по **ID магазина или канонической ссылке** в пределах площадки. Одинаковое название или фотография не объединяют компании автоматически. Под поставщиком показаны товары текущих сборов, а не весь ассортимент компании. Неопределённые поставщики остаются отдельными товарами.

Для трёх маркетплейсов сохраняются их ID предложений. На других сайтах источник имеет вид `web:example.com`, а ID обычно вычисляется по канонической ссылке. Трекинговые параметры удаляются; параметры вариантов товара сохраняются. Это локальный ID расширения, а не официальный ID сайта.

Если ссылки нет, используются явный `data-product-id`/SKU либо отпечаток названия, изображения и цены. Такие записи помечаются `native-id` или `card-fingerprint`, ссылка остаётся `null`. Отпечаток без официального ID может измениться при изменении цены или названия; точное удаление дублей таких карточек не гарантируется.

## Исходные карточки и JSON

С включённым сохранением исходников сохраняется очищенная разметка найденных карточек с их ID и адресом выдачи. Скрипты, формы, поля ввода, обработчики событий и посторонние атрибуты удаляются. Полные страницы, cookies, полные тела сетевых ответов и данные входа не сохраняются. Для источников без DOM снимок содержит нормализованный товарный `record` вместо разметки. Карточки больше 20 000 символов сохраняются только в нормализованном виде.

**Сырой JSON** добавляет `raw_cards`: очищенный HTML или нормализованный товарный `record` для источника без DOM. **Переразобрать карточки** применяет текущий движок к этим снимкам без новой загрузки сайта. Снимок не восстановит сведения, которых в нём не было, включая отсутствующее имя магазина.

Схема экспорта — **3**. Поля верхнего уровня: `collection_mode`, `sources`, `exported_at`, `total_products`, `total_suppliers`, `total_tasks`, `tasks`, `pages`, `suppliers`, `unresolved_products`, `products`; в сыром экспорте также `raw_cards`.

Строка наблюдения дополнительно содержит `observation_id`, `task_id`, `checkpoint_id`, `page_index`, `card_index`, `page_card_key`, `capture_status`. Товар содержит `source`, `product_id`, `title`, `product_url`, `supplier_id`, `shop_name`, `supplier_url`, `price`, `minimum_order`, `image_url`, `query`, `search_type`, `collected_at`, `last_seen_at`, `source_page_url`, `sightings`, `task_ids`, `field_sources`, `field_confidence`, `identity_type`, `extraction_confidence`; при расхождении цен — `data_conflicts`; после проверки может появиться `detail_checked_at`. ID — строки, даты — ISO 8601 UTC, цена и минимальный заказ — строки без угадывания валюты и единиц. Отсутствующие значения — `null`. CSV защищает значения от интерпретации как формулы Excel.

Результаты и образцы хранятся локально в браузере; на внешний сервер они не отправляются. Переходы и догрузка используют обычную работу сайта.

```bash
cd /workspace/1688Viewer
npm ci --cache /tmp/1688viewer-npm-cache --ignore-scripts --no-audit --no-fund

```

Тесты проверяют отдельные появления повторных ID с разными ценами, несколько страниц/заданий, полностью повторную следующую страницу, SPA-переход, догрузку дубликата, паузу/перезапуск/продолжение без технических копий, импорт/переразбор повторных строк и сохранность JSON/CSV/Excel. Проверены контролируемые страницы 1688, Alibaba и Made-in-China. Тесты также проверяют показ/скрытие миниатюр, сохранение режима истории, ошибки изображений, разрешения на серверы картинок, отмену подготовки, экспорт без загрузки картинок и настоящий XLSX со встроенными JPEG, общими медиафайлами и привязкой рисунков к ячейкам. Структура файла и миниатюры дополнительно проверены независимым считывателем openpyxl; настольного Excel в облаке нет, нажатия + / − в нём здесь не проверялись. Тесты также проверяют отдельную вкладку истории, удаление одной и всех проверок, сохранность общих и импортированных товаров, восстановление полей, запрет удаления во время выполнения/продолжения, выборочный экспорт и обновления между вкладками. Они также проверяют несколько поисков, снимки заданий, накопительную память, перезапуск, очистку, фильтр заданий и структуру настоящего XLSX с защитой строк от исполнения как формул. Тесты проверяют реальный DOM и интерфейс в Chromium: три маркетплейса, неизвестные структуры, изменение классов, Shadow DOM, JSON-LD, варианты товаров, пустые ссылки, повторный анализ, пагинацию, догрузку, новые вкладки, неоднозначный выбор, обучение по образцу, доступ к доменам, сохранение, обогащение, капчу и экспорт. Chrome API в интеграционных тестах моделируется. Полный цикл капчи и продолжения кнопкой popup проверяется отдельно для 1688, Alibaba и Made-in-China на контролируемых страницах с изменением разметки и перезапуском фона. Фикстуры не являются живыми страницами площадок.

Нативная проверка установки и скачивания запускается отдельно:

```bash
npm run test:extension
```

В облачном Chromium установка запрещена управляемой политикой `ExtensionInstallBlocklist: ["*"]`; эта проверка заблокирована. Политики не изменяются. Живые страницы трёх маркетплейсов и нативная работа расширения в пользовательском Chrome здесь не проверены: облачный прокси отклоняет соединения с HTTP 403. Доступ к доменам сохранён в сетевом черновике; сохранение черновика не применяет сетевую политику автоматически. Снимки и тестовые страницы не подтверждают совместимость всех текущих страниц сайтов.

Дополнительные файлы: `data-sources.js` — семантика, встроенный JSON и данные приложения; `page-data.js` — чтение разрешённых полей в MAIN; `observer.js` — динамические изменения DOM; `response-observer.js` и `response-bootstrap.js` — опциональное наблюдение и разрешение для вкладки.

Основные файлы: `navigation.js` — анализ кнопок и переходов; `generic.js` — общий анализ карточек; `engine.js` — сбор источников и повторный анализ; `shared.js` — идентификаторы, ссылки и объединение; `content.js` — работа со страницей и выбор образца; `background.js` — этапы и вкладки; `dashboard.*` — таблица, журнал и управление; `popup.*` — быстрый запуск; `export.*` — экран выгрузки Excel; `images.js` — локальная подготовка миниатюр; `excel.js` — OOXML и ZIP.
