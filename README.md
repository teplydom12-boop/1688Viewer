# Supplier Viewer 0.2

Одно расширение Chrome для поиска поставщиков на **1688, Alibaba и Made-in-China**. Вы выполняете поиск по тексту или фото на самом сайте, а расширение собирает выдачу, проверяет страницы товаров и показывает **таблицу поставщиков с деревом найденных товаров**.

## Что изменилось после первого сбора

В присланном результате версии 0.1 было 54 товара и ни одного имени магазина. В предоставленной разметке выдачи имена и ссылки магазинов не показаны: их нельзя восстановить одним изменением CSS-селекторов. Теперь есть отдельный этап проверки страниц товаров.

Поиск по фото использует кликабельные блоки без обычных ссылок. Их `data-renderkey` содержит идентификатор товара и иногда идентификатор поставщика. Новый движок использует эти данные. На сохранённых пользователем страницах восстановлено **59 товаров из текстового поиска** (включая рекламные предложения) и **60 товаров из поиска по фото**, сгруппированных по **32 идентификаторам поставщиков**. Это идентификаторы магазинов, а не подтверждённые названия компаний.

Присланные HTML и JSON не включены в репозиторий. В тестах используются небольшие обезличенные примеры соответствующей структуры.

## Установка или обновление

1. Скачайте `supplier-viewer-0.2.0.zip` из чата и распакуйте архив.
2. Откройте `chrome://extensions`, включите **Режим разработчика**.
3. Нажмите **Загрузить распакованное расширение**, выберите папку `supplier-viewer` с `manifest.json`.
4. Если расширение уже установлено из папки проекта, замените её файлы и нажмите кнопку обновления расширения в `chrome://extensions`. Обновите открытые вкладки маркетплейсов.
5. Для установки из GitHub: **Code → Download ZIP**, распакуйте проект и загрузите папку **extension** внутри него.

Если устанавливаете новую копию отдельно от старой, сначала экспортируйте данные из старой, отключите старое расширение, затем импортируйте JSON в новой версии. Автоматического переноса между разными идентификаторами расширений нет.

Нужен Chrome на компьютере. Ключ ChatGPT, отдельная программа или сервер для этого этапа не требуются. Расширение запрашивает доступ к трём маркетплейсам, локальному хранилищу и скачиванию файлов. Если Chrome управляется организацией, её политика может запрещать установку.

## Рекомендуемый первый запуск

1. Откройте маркетплейс и выполните обычный поиск или поиск по фото.
2. Нажмите расширение → **Открыть таблицу поставщиков и журнал**.
3. Выберите вкладку с выдачей. Для проверки оставьте **1 страницу** и паузу **3 секунды**.
4. Оставьте включёнными догрузку, получение магазинов и сохранение исходных карточек.
5. Нажмите **Начать сбор**. Сначала собирается выдача, затем недостающие сведения магазина извлекаются из страниц товаров в отдельной рабочей вкладке.
6. Откройте ветку поставщика в таблице и сравните несколько строк с сайтом.
7. Сохраните JSON или CSV. В JSON есть дерево поставщиков и плоский массив товаров; CSV содержит по одной строке на товар с полями поставщика и подходит для Excel.

Метка поиска необязательна. Для фотографии можно указать «Фото №1». Изображение вы загружаете средствами маркетплейса; расширение использует уже готовую выдачу.

### Как обработать уже собранный файл

Нажмите **Импорт JSON** и выберите файл версии 0.1 или 0.2. Затем нажмите **Проверить собранные карточки**. Расширение пройдёт по товарам без имени или ссылки магазина. Предыдущие сведения не теряются, пустые поля не затирают известные значения.

Проверка карточек медленнее сбора выдачи: это отдельная загрузка каждого товара. Она идёт последовательно, с указанной паузой. Рабочая вкладка остаётся открытой для осмотра; во время задания не меняйте её адрес.

Если несколько товаров уже связаны надёжным ID или URL поставщика, проверяется одна его карточка, а полученные имя и ссылка заполняют недостающие поля связанных товаров. Цены и характеристики других товаров не копируются. Это сокращает число переходов; в выдаче без идентификаторов товары приходится проверять отдельно.

## Управление и прозрачность

- Видны текущий этап, число страниц, очередь карточек, прогресс и журнал последних 100 действий.
- **Пауза** сохраняет состояние и уже прочитанные карточки, в том числе при прерывании прокрутки.
- **Продолжить** возобновляет сохранённый этап. Перед продолжением можно изменить паузу между переходами.
- **Рабочая вкладка** открывает страницу, которую сейчас обрабатывает расширение.
- При обнаружении капчи, формы входа, ограничения частоты запросов, ошибки или повторной выдачи задание приостанавливается. Никаких автоматических решений капчи или повторных запросов в цикле нет.
- Если кнопки следующей страницы нет, собранные результаты сохраняются; можно перейти вручную и начать следующий сбор.
- Лимит одного запуска: 1–20 страниц; пауза между переходами: 1–30 секунд. Прокрутка тоже ограничена, а неполнота отмечается предупреждением.

Умеренный темп и последовательная обработка снижают нагрузку, но не гарантируют отсутствие капч. Разблокировку, вход и проверку безопасности выполняет пользователь, после чего нажимает **Продолжить**.

## Таблица поставщиков

Поставщики объединяются по **идентификатору магазина или канонической ссылке** в пределах площадки. Если товар содержит и ID, и URL, эти сведения связывают записи одной витрины. Одинаковое название или фотография не объединяют компании автоматически. Одна компания с несколькими магазинами или на разных маркетплейсах может остаться несколькими строками, пока её тождество не подтверждено.

Под каждым поставщиком показываются его найденные товары, цены, минимальный заказ и ссылки. Это товары текущих сборов, а не полный ассортимент компании. Неопределённые поставщики вынесены отдельно; если ID известен, а название нет, интерфейс прямо сообщает, что имя магазина не получено.

## Устойчивость к изменениям сайта

Движок использует несколько источников:

1. JSON-LD Product и допустимые JSON-данные страницы, если они присутствуют.
2. Идентификаторы карточек и метаданные `data-renderkey` на 1688.
3. Семантические признаки DOM, ссылки на товары и магазины, префиксы классов независимо от меняющихся суффиксов.
4. Отдельный этап обогащения из страниц товаров.

Поле `field_sources` показывает, каким способом получены сведения. Если данные отсутствуют, они остаются `null`; бренд товара не считается поставщиком.

Это **не самообучающийся ИИ** и не гарантия работы на любом сайте после любого редизайна. Сейчас правила ссылок поддерживают три площадки. Для нового сайта нужны правила идентификации товаров и компаний и проверки на его разметке. Отдельная программа с анализом через модель может быть следующим этапом, но сначала полезно накопить проверяемые исходные данные.

## Исходные карточки и повторный анализ

С включённым сохранением исходников сохраняется очищенная разметка найденных карточек с их ID и адресом выдачи. Из неё удаляются скрипты, формы, поля ввода, обработчики событий и посторонние атрибуты. Полный HTML страницы, cookies, браузерные сетевые ответы и данные входа не сохраняются.

**Сырой JSON** содержит `raw_cards` вместе с нормализованными данными. **Переразобрать карточки** применяет текущий движок к сохранённым карточкам без повторной загрузки сайта. Это позволяет уточнять правила извлечения позже. Карточки больше 20 000 символов не сохраняются как HTML, чтобы не обрезать разметку посередине; нормализованные товары сохраняются.

Снимок не может восстановить имя магазина, которого на странице не было. Для этого нужна проверка карточки товара. Исходники нужны для повторного анализа присутствующих данных, а не для угадывания отсутствующих.

Все результаты хранятся локально до очистки или удаления расширения. На внешний сервер они не отправляются. Догрузка и переходы используют обычную работу маркетплейса в вашем браузере.

## Формат JSON

Версия схемы — **2**. Экспорт содержит `sources`, `exported_at`, `total_products`, `total_suppliers`, `pages`, `suppliers`, `unresolved_products` и `products`. В сыром экспорте также есть `raw_cards`. Плоский массив `products` сохранён для совместимости с последующей обработкой.

Поля товара: `source`, `product_id`, `title`, `product_url`, `supplier_id`, `shop_name`, `supplier_url`, `price`, `minimum_order`, `image_url`, `query`, `search_type`, `collected_at`, `last_seen_at`, `source_page_url`, `sightings`, `field_sources`; после проверки может появиться `detail_checked_at`.

ID хранятся строками, даты — ISO 8601 UTC, цена и минимальный заказ — строками без угадывания валюты и единиц. Отсутствующие поля — `null`. Импорт объединяет товары по площадке и ID. CSV экранирует значения, которые Excel мог бы интерпретировать как формулы.

## Разработка и проверка

Node.js 22+, Python 3 для архива, Chromium для браузерных тестов. По умолчанию браузер — `/usr/bin/chromium`; `CHROMIUM_PATH` задаёт другой путь.

```bash
cd /workspace/1688Viewer
npm ci --cache /tmp/1688viewer-npm-cache --ignore-scripts --no-audit --no-fund
npm run check
npm test
npm run package
```

Архив: `dist/supplier-viewer-0.2.0.zip`. В него не входят зависимости, тесты, пользовательские файлы и данные сборов.

Обычные тесты проверяют разбор DOM в Chromium, метаданные поиска по фото, JSON-LD Alibaba, DOM Made-in-China, сохранение, обогащение, паузу при капче, возобновление, таблицу и экспорт. Chrome API в интеграционных тестах моделируется.

Отдельная проверка установки и нативного скачивания:

```bash
npm run test:extension
```

В облачном Chromium установка запрещена политикой `ExtensionInstallBlocklist: ["*"]`; эта проверка остаётся заблокированной. Управляемые политики не изменяются. Живой доступ к маркетплейсам из этой облачной среды не проверен; 1688 блокируется сетью. Разбор предоставленного пользователем HTML и тестовых страниц не подтверждает полную совместимость актуальных страниц Alibaba, Made-in-China или страниц товаров 1688. Для окончательной проверки нужен запуск в вашем Chrome.

Основные файлы: `extension/engine.js` — извлечение и повторный анализ; `shared.js` — правила ссылок, объединение и группы; `content.js` — работа со страницей; `background.js` — этапы, хранение и экспорт; `dashboard.*` — таблица и журнал; `popup.*` — быстрый запуск.
